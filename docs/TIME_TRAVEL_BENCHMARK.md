## 1. 这轮实际修的 bug

用户反馈"穿越模式好多 bug"但没给具体截图，没有凭空猜，直接读代码 + 跑复现脚本，
找到了两个真实、可复现的问题。

### 1.1【核心 bug】五年结局的"战绩评级"系统从写好那天起就是死代码

**现象**：不管你五年打得多好——哪怕拿了 2 个总冠军、管理层信任度拉满——生涯结束时
看到的都是千篇一律的"重建续约 · 4年7薪资"或"带着成果离开"，从来不会看到游戏里其实
写好了的"王朝建筑师 🏆"或"历史改写者"这种更有分量的结局标签。被裁时也只会看到
扁平的"在低谷中下课"。

**根因**：`js/story/eventEngine.js` 的 `deriveEnding()` 会根据冠军数 + 信任度算出
四档叙事结局（王朝建筑师 / 历史改写者 / 未完的革命 / 在压力中离任），这是游戏最初设计
的"五年打完给你一个有分量的评价"系统。但后来加了"连续战绩差会被裁 / 五年后谈续约"这个
更具体的机制（`js/modes/careerContract.js`），这个新系统有自己的一套结局标签，而且
**从写好那天起从来没有调用过 `deriveEnding()`**。`js/app.js` 里负责调度的
`queueNextTimeTravelEvent()` 用的是 `employed === progressed`（对象引用相等）来判断
"要不要退回去走 `finalizeCareerEnding()` 这条老路"——但 `evaluateCareerEmployment()`
只要真的发生了解雇/续约这类终局事件就必然返回一个新对象，这条引用相等的判断永远走不到
该走的分支。等于两套结局系统各写各的，新的那套（`careerContract.js`）胜出，旧的那套
（`deriveEnding()`）被晾在那儿，连它自己的单元测试都是直接调用它本身、从来没有走过完整
的游戏流程，所以半年多都没人发现。

**实锤复现**（修复前）：

```
2 个总冠军 + 信任度 70 的五年生涯
deriveEnding() 直接算出来：{ id: 'dynasty-builder', label: '王朝建筑师' }
真实游戏流程走出来的结局：ending === null（续约 offer 阶段，之后accept/decline
只会写入 "renewed-career" / "left-as-legend"，永远到不了 dynasty-builder）
```

**修复**：没有砍掉任何一套系统，而是让两套系统叠加——`careerContract.js` 现在会在
解雇/接受续约/拒绝续约三个分支里都顺手算一次 `deriveEnding(root)`，挂在
`ending.narrativeTier` 上。原来的"续约方案/被裁/离开"仍然是**玩家做出的具体选择**
（机制层），`narrativeTier` 是**五年打得怎么样的客观评价**（叙事层），两者互不冲突、
一起展示：生涯报告和状态提示现在会同时显示"重建续约 · 4年7薪资（王朝建筑师）"。

- 改动文件：`js/modes/careerContract.js`（接入 `deriveEnding`）、`js/app.js`
  （`careerStateNotice()` / `renderTimeTravelReport()` 展示 `narrativeTier`）。
- 新增 3 条回归测试（`tests/careerContract.test.js`），并做过 mutation check：
  删掉 `narrativeTier` 这行代码后测试立刻报错，确认测试真的能抓住这个回归。
- 没有改变任何现有已通过的测试断言，`ending.id`（续约方案的那部分）保持原样，
  纯叠加。

### 1.2【小修】穿越首页文案"擅自执教"用词和实际剧情不符

`index.html` / `js/i18n-phrases.js` 的穿越入口文案写的是"回到历史一年**擅自**执教
一支球队"——但实际流程是面试、拿到正经 offer 才上任（`generateInterviewOffers` /
`acceptInterviewOffer`），英文翻译也只是中性的"take over a team"，没有"未经授权"
的意思。中文这边词不达意，已经在 `docs/WORKNOTE.md` 的"已知未处理"里挂了很久，这次
顺手改成"回到历史一年穿越执教一支球队"，跟英文和实际剧情对齐。

### 1.3 还没处理、但这轮顺手发现的一个更深的问题（见第 3.2 节）

`frontOfficeTrust`（管理层信任）、`mediaPressure`（媒体压力）、`timelineDivergence`
（时间线偏离）这三个数值**玩家能看到、会随每个故事选择变化，但在机制上几乎是摆设**：

- 是否被裁**只看连续两个赛季的胜率**，和信任度/压力完全无关——信任度刷到 95 还是
  跌到 5，只要连续两年输球一样被裁。
- 续约 offer **永远是同样的两个固定模板**（`OFFER_TEMPLATES` 写死 4年/薪资7/权限88
  和 2年/薪资13/权限54），不管你拿了 0 个冠军还是 3 个冠军、信任度是 10 还是 95，
  续约时看到的两个选项字面意义上一模一样。

这个不是"写错了"的 bug，是设计上还没把"叙事层数值"和"机制层决策"打通——1.1 修的是
"结局标签不互通"，这条是"结局**内容**不受你五年的选择和战绩影响"，影响更大但改动也
更大（需要重新设计续约 offer 的生成规则），所以单独记在这里，放进第 4 节的优先级建议，
不在这轮直接动手。

## 2. 现状盘点：穿越生涯现在到底有什么

跑模式之前先说清楚家底，免得对照分析变成"没有就是菜"的空话。

- **身份**：玩家穿越回选定的历史年份，面试拿 offer（重建队/中游队/争冠队三选一，
  权限、首年目标、信任度、压力各不相同），身份是**球队经理兼教练**，不是球员。
- **五年篇章**：6 个写死的剧情事件，按年份顺序触发（第一年两个、二到五年各一个），
  每个事件 2-3 个选项，影响信任度/压力/时间线偏离/人物关系（老板/GM/教练/球员/媒体）。
- **历史偏离**：时间线偏离度会累积，目前只是展示用的数字，不反推任何具体内容变化
  （没有"偏离到一定程度解锁隐藏事件"之类的机制）。
- **经营系统是共享的联盟生涯内核**：选秀、交易市场（含多对多 + 选秀权 + 推荐配平）、
  球员发展、球队评估建议、自由市场、季后赛，这些穿越生涯和"联盟经理"模式共用同一套
  `js/engine/season.js` + `js/engine/seasonMarket.js` 等引擎，不是穿越专属的阉割版。
- **结局**：五年后触发续约谈判（两个固定方案）或者因连续两个赛季胜率低于 40% 被裁，
  现在加上本轮修的叙事评级，能看到"重建续约（王朝建筑师）"这种组合展示。
- **分享卡**：生涯结束后可以生成一张战绩分享卡（`js/story/endingShareCard.js`）。

## 3. 对照 NBA 2K（MyGM / MyNBA）

2K 的生涯/经理模式打磨了十几年，不可能也不需要全部抄过来，挑对我们当前架构（本地
静态网页、无后端、单人存档）**真正能落地、性价比高**的部分说。

| 维度 | 2K MyGM/MyNBA 怎么做 | 我们现在怎么做 | 差距 / 建议 |
|---|---|---|---|
| **续约谈判** | 球员/教练续约有明确的"开价-还价"多轮拉锯，球员会根据市场薪资、年龄、表现提出具体诉求（年限、角色、球队方向） | 教练自己的续约是两个固定模板，和战绩/信任度完全无关（见 1.3） | 续约 offer 应该按 `careerPerformance()` 已经算出来的冠军数/胜率动态生成第三个（甚至更多）选项，而不是永远只有两个写死模板 |
| **GM 信任/老板信心** | 老板信心值直接决定预算、容错空间、续约态度，掉到底线直接开除 | `frontOfficeTrust` 只用来决定续约方案的"触发条件"（还触发不到，见 1.3），不影响预算或任何经营参数 | 让信任度真正联动一些可感知的经营参数，比如信任度低于某个阈值时交易额度/球探预算打折，这样玩家能感受到"信任度"不是纯装饰 |
| **解雇判定** | 不是纯胜率，还看是否完成赛季初设定的目标（进季后赛/争冠），目标分级 | 纯两个赛季胜率 <40% | 已有的 `offer.firstYearGoal`（如"进入季后赛"）其实是个现成的钩子，目前完全没接入解雇判定——明明写了"首年目标"却从没检查有没有达成 |
| **球队文化/更衣室关系** | 球员个体好感度、要求交易、拒绝某些合同条款 | 只有聚合的 `relationships.players` 一个数字，不针对具体球员 | 中期：把关系精确到核心球员个体，配合已有的"交易偏好/挂牌熟悉感"标签体系（已经在自由市场做过） |
| **多个赛季的持续故事** | MyNBA 可以一直打下去，故事线围绕球队的长期轨迹 | 硬性 5 年封顶，之后故事内容为空 | 这是已经记录在案的"首个完整版本是五年篇章"的既定范围，不算 bug，但第 4 节会给一个低成本的"续篇"思路 |
| **草稿/阵容真实感** | 球探报告、潜力隐藏值、选秀权保护条款 | 已经有（选秀权交易、球探/价值标签系统），这块我们已经不差 | 无需额外投入 |
| **历史改变的感知** | 2K 没有这个设定（不是穿越题材） | 我们独有：`historyChanges`（当前时间线冠军 vs 真实史实冠军对比） | 这是我们的差异化卖点，但目前只在"生涯报告"里一行文字带过，没有在 UI 上做任何强调——应该放大，而不是跟别的数字平铺 |

## 4. 对照 FIFA / EA FC 生涯模式（经理人向）

| 维度 | FIFA/FC Career Mode 怎么做 | 我们现在怎么做 | 差距 / 建议 |
|---|---|---|---|
| **董事会目标 + 信心值直接定生死** | 赛季初给明确可量化目标（联赛排名/杯赛轮次），完成与否直接决定信心值涨跌和续约态度 | `offer.firstYearGoal` 是文本描述，从未被任何代码检查是否达成（见上表） | 这是和 2K 那条重叠的同一个洞——**最高优先级的廉价改进**：只需要在赛季结束时对比 `firstYearGoal` 和实际战绩/排名，就能把这套早就写好但从未使用的字段用起来 |
| **赛前/赛后新闻发布会** | 教练在发布会上选择语气（自信/谦虚/挑衅），影响球员士气和媒体关注度 | 我们的"故事事件"本质上就是同类机制（选择影响信任/压力/关系），只是触发频率低（6 个事件铺满 5 年） | 不需要抄新闻发布会这个皮，但可以借鉴"触发频率"——现有事件密度对一个"五年"的叙事模式来说偏稀疏，年均刚超过 1 个选择点 |
| **球员选秀权/潜力动态成长** | 新秀潜力值会随训练/出场时间浮动变化（非固定上限） | 已有潜力/成长系统（`js/modes/playerDevelopment.js`），不比 FIFA 差 | 无需额外投入 |
| **教练在多家俱乐部间跳槽的职业生涯** | 可以在不同俱乐部之间跳槽，声望累积影响后续能拿到的 offer 质量 | 穿越生涯被裁/续约后故事直接终结（epilogue），没有"跳槽去下一家球队继续经理生涯"的设计 | 中期：被裁或主动离开后，与其直接游戏结束，不如开放"用当前声望值（可以直接复用 `frontOfficeTrust` 的峰值）去下一轮面试，开始新的五年"——复用现有的面试系统，几乎零新增代码，只是把"结束"改成"轮换到下一段" |
| **转会市场的真实多方博弈** | 其他俱乐部会抢人，玩家会因为犹豫丢掉目标 | 我们已经有"外部主动报价 + 拒绝后不重复刷同一份报价"机制 | 无需额外投入，已经做得比较完整 |
| **球员角色扮演（Player Career，非 Manager）** | FIFA 也有"扮演一名球员"打比赛、练位置、博转会的模式，和 Manager 模式是两条线 | 我们目前穿越是"经理兼教练"，没有"穿越回去自己上场打球"的模式（这正好是用户很早之前问过的问题） | 这是一个独立的新模式方向，不是穿越生涯的修修补补，需要单独立项讨论（球员属性成长、位置、出场时间、个人数据驱动的剧情），不建议现在顺手加 |

## 5. 优先级建议

按"复用现有数据结构的程度"和"玩家能感知到的提升"排序，不是越花哨越靠前。

### P0（下次动手时优先做，复用度最高，几乎不需要新内容）

1. **用 `firstYearGoal` 真正判定"有没有完成首年目标"**，接入解雇/信任度逻辑——
   这个字段已经存在了五年篇章的第一个事件里（`generateInterviewOffers` 生成时就带着），
   现在完全没人读它，是最便宜的一次"让已有数据产生意义"的改动。
2. **续约 offer 按战绩动态生成，不要永远两个固定模板**——复用 `careerPerformance()`
   已经算出来的 `championships`/`winRate`，冠军越多应该解锁更好的续约条件（更高权限/
   更长年限），而不是像现在这样和 1.1 修复前的"王朝建筑师"一样被晾在那儿。
3. **把"历史改变"（`historyChanges`）在 UI 上做成独立展示区**，这是我们相对 2K/FIFA
   最独特的卖点，目前被埋没在生涯报告的一行文字里。

### P1（中期，需要一点新内容但复用现有系统）

4. **被裁/离开后可以"跳槽"开始下一段五年**，复用面试系统，不是另起炉灶，用声望值
   （可以直接从 `frontOfficeTrust` 峰值导出）影响下一轮 offer 质量。
5. **把聚合的 `relationships.players` 拆到核心球员个体**，配合已有的交易偏好/熟悉感
   标签体系，做"核心球员因为你的某个选择要求交易"这类反馈。

### P2（长期，需要独立设计讨论，不建议现在顺手做）

6. **"穿越回去自己打球"的玩家生涯模式**——这是一个和"经理兼教练"完全不同的产品
   方向（属性成长、位置、个人数据驱动剧情），应该单独立项，不要塞进穿越生涯的修补里。

## 6. 开放问题（需要你确认才能往下推进）

- P0 的三条如果要动手，是三条分别单独提交，还是合成一轮一起做？（和之前拆分
  "一个问题一个提交"的惯例一致，建议分开。）
- 续约 offer"按战绩动态生成"的具体数值曲线（冠军数对应多少年限/薪资/权限提升）
  需要你定一版初稿，还是我先给一版建议数值再让你调？
- "跳槽开始下一段五年"是否真的需要——这会让穿越生涯从"一次性五年故事"变成
  "可以无限轮换的生涯"，偏离了当初"首个完整版本是五年篇章"的既定范围，需要你明确
  是否要扩大这个范围。
- 1.3 提到的"信任度联动经营参数"要联动到哪些具体数值（预算/球探/交易额度），需要
  先列一份清单再实现，避免凭空编一套数值体系。
