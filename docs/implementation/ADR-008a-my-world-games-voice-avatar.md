## 1. N-1d My Games：仓库里真实存在的存档

### 1.1 存档清单（以代码为准）

| 来源 | 键 | 能恢复什么 | 槽位 | 归属账号 |
|---|---|---|---|---|
| 根存档 `js/data/saveRoot.js` | `cls_root_v3`（+ 写入临时键 `cls_root_v3_tmp`） | 穿越生涯（`leagueCareer.kind === "timeTravel"`）、联盟经理/赛季、进行中的比赛快照 `liveGame` | **整台设备 1 个** | 写入时记录 `profile.accountId`，**恢复时不校验** |
| 旧赛季键 | `cls_season_v1` | 旧版普通赛季；启动时迁入根存档 | 1 个 | 无 |
| 中途存档 `js/data/savegame.js` | `cls_savegame_v1` | 金币挑战（市场）、预算轮抽/选人、比赛设置、传奇挑战、锦标赛、比赛中途、结果页 | **整台设备 1 个**；存一个模式会覆盖另一个 | **没有**账号字段 |
| 账号 `js/data/account.js` | `cls_accounts_v1` | 不可"恢复"：卡牌收藏、冠军、排位记录（属于历史/荣誉） | 每账号 | 是 |
| 联机战绩 `js/online/record.js` | `courtside-online-record` | 不可恢复，只是本机战绩 | 1 个 | 无 |
| 不落盘 | — | 排位单场、每日挑战、联机房间（状态在服务器）、快速开打 | — | — |

结论：
- 今天最多同时存在 **2 个**可恢复入口：一个"生涯"（根存档）+ 一个"中途进度"（`cls_savegame_v1`）。不会有你示例里的四行同时存在，除非改存储（不在本任务范围）。
- 金币挑战、锦标赛只有在玩家点过"保存"或页面关闭前自动保存时才有进度。My Games 只能如实显示"有一个中途进度：锦标赛 · 8 强"，不能凭空列出。
- 已结束的记录在根存档（`coach.stints`、`management.seasonHistory`、`story.ending`）和账号（冠军、收藏、排位）里，可以分成"历史"区展示，不能放在"继续"区。

### 1.2 P0 隐私缺口（必须先定）

两个可恢复槽位都是**设备级**的。切换账号后，A 账号的穿越生涯和中途进度会原样出现在 B 账号的首页"继续"里（My World 现在也照读）。这与"账号切换时不能展示其他账号的私人存档"冲突。

建议做法（只加归属标记，不迁移存档格式）：
1. `writeSave()` 写入时附带 `ownerAccountId`（游客为 `null`）；根存档已有 `profile.accountId`，直接使用。
2. My Games 只显示 `owner === 当前账号` 的条目；游客只显示 `owner === null` 的条目，并注明"仅保存在本设备"。
3. 旧存档没有归属：**需要你决定**（见 §5 Q1）。
4. 首页"继续生涯"按钮和 My Games 用同一个归属判断，避免两处结论不一致。

### 1.3 SaveIndex 契约（只读，不统一格式）

```js
// js/data/saveIndex.js（计划）：每个来源一个 provider，只读 + 委托原流程
{
  saveId: "root:career" | "session:tournament" | ...,  // 稳定，同一槽位只出一行（自动/手动不会重复）
  modeId: "timeTravel" | "franchise" | "goldChallenge" | "tournament" | "legend" | "draft" | ...,
  title, subtitle,            // 例："锦标赛 · 8 强"；文案取自原存档的真实字段
  updatedAt,                  // 原存档的时间戳；没有就不显示时间
  status: "resumable" | "finished",
  ownerAccountId,             // null = 游客/本机
  source: "cls_root_v3" | "cls_savegame_v1",
}
```
- 恢复：调用原有 `resumeLongCareer()` / `continueFromSave()`；删除：调用原有 `deleteCareerSave()` / `clearSave()`。My Games 不自己读写存档内容。
- 进行中的比赛快照（`liveGame`、`screen: "game"`）归到所属的那一行，不单独成一行，也不算永久存档。

### 1.4 验收
- 每种真实存在的存档都能在 My Games 出现一次且只出现一次；点"继续"进入原模式的原状态。
- 切换账号后看不到别人的存档；游客有本机提示。
- 删除后首页和 My Games 同时消失。
- 改名：「我的旅程」→「我的游戏记录 / My Games」。

## 2. N-1e Player Voice：后端现状与方案

### 2.1 现状
- 现在的 My World 底部是一个大反馈卡：玩家填写，点"复制"后跳到 GitHub Issues（`FEEDBACK_URL`）。没有任何服务端存储。
- 项目唯一的后端是联机 WebSocket 服务器 `server/online-server.mjs`：
  - 已有：账号（scrypt）、注册限流 `createRegistrationGate`、单条消息上限 `MAX_MESSAGE_BYTES`、TLS 传输、JSON 文件持久化（用户主目录，原子写）。
  - 没有：HTTP 接口、管理员角色、反馈存储。
  - **生产环境还没部署**（没有正式 `wss://` 域名），所以现在不论用哪种方案，都不能真正把反馈送到你手里。

### 2.2 方案比较

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 在现有服务器加一个 `feedback` 消息类型 → 追加写入 `~/.courtside-feedback.jsonl`；管理员用本地脚本查看/汇总 | 复用限流、长度上限、TLS 和持久化；不需要新基础设施 | 要等生产服务器上线；游客离线时发不出去 |
| B | 同一个 Node 进程加 `POST /feedback` HTTP 接口 | 不需要 WebSocket 连接 | 要新增 HTTP 路由和 CORS；收益不比 A 大 |
| C | 第三方表单服务 | 最快 | 玩家数据交给第三方，需要隐私政策；token 不能放前端 |

### 2.3 无论选哪种都要守的规则
- **没有服务器确认就不显示"提交成功"。** 离线时如实显示"已保存在本设备，联网后发送"（本地队列），或者只提供复制。
- 三种类型：建议 / Bug（自动附版本号、设备信息，可选截图在第二版）/ 评价（1–5 星 + 可选评论）。
- 防刷：每账号/每 IP 每小时上限（沿用注册限流的写法）、正文 ≤ 1000 字、去掉 HTML。
- 隐私：不收集存档内容、不收集联系方式（除非玩家主动填写）。
- 管理：第一版是服务器上的只读脚本（列表、按类型统计、平均分），不做网页后台。
- 每日任务后的评价邀请：自愿，可以关掉，**与奖励无关**，不出现"给五星领奖励"。
- UI：右上角一个小图标打开面板；删除 My World 底部的大反馈卡。

## 3. N-1f 3D Avatar：可行性

### 3.1 技术栈
- 项目没有打包器（浏览器直接加载 ES Module），也没有任何 WebGL 代码。比赛球场是 DOM/CSS，和 3D 完全独立，**GameSim 不需要改**。
- 推荐 **Three.js**（MIT 许可）：把 `three.module.min.js` 和 `GLTFLoader` 放到 `js/vendor/`，只在打开 My World 时用 `import()` 动态加载，其他页面零成本。
  - 体积：约 0.7 MB 未压缩 / 约 170 KB gzip（还需实测，见风险）。
- 模型格式 GLB/glTF：一套风格化骨架，发型、服装、鞋子作为可替换的子网格，用 `visible` 切换，不做实时换衣物理。
- 动画：Idle 1 个 + 拖动旋转；庆祝动作放到下一阶段。
- 离开 My World 时：停止 `requestAnimationFrame`，`dispose()` 渲染器和几何体，避免手机内存上涨。
- 回退：`getContext("webgl")` 失败、模型加载失败或超时（例如 4 秒）→ 显示现有 CSS 静态形象。可选：设备内存很小时直接用静态形象。

### 3.2 美术与授权（仓库是公开的，提交进去的资源等于公开再分发）

| 来源 | 许可 | 是否适合 |
|---|---|---|
| Quaternius 风格化角色 | CC0 | **适合**：可商用、可再分发、不需要署名 |
| Kenney 角色包 | CC0 | 适合，风格偏方块 |
| Mixamo（Adobe） | 可在作品里使用，但不能把原始模型/动作当素材再分发 | 不适合直接放进公开仓库 |
| Ready Player Me | 服务状态需要核实 | 不建议依赖第三方在线服务 |
| VRoid 模型 | 每个模型的授权不同 | 逐个核查，默认不用 |
| 自制 / 外包 | 合同约定 | 长期方案 |

建议：垂直切片只用 CC0 资源，在 `docs/ASSET_CREDITS.md` 记录来源和版本。另外，CC0 现成角色未必自带"多发型、多服装"的子网格，可能需要用 Blender 拆分（美术工作量，见风险）。

### 3.3 身份规则
- 外观保存在账号资料里（例如 `account.avatar`），游客保存在本机。**不写进根存档，也不和 Reborn 的职业人物共用。**
- 外观身高、体型**永远不影响**任何比赛属性；以后 Reborn 如果复用这个形象，竞技身体数据仍由职业模式规则决定。

### 3.4 垂直切片（建议拆成 3 个小提交）
1. Spike：加载一个 CC0 角色、拖动旋转、Idle；桌面和手机各截图；测首帧时间和帧率。
2. 两种发型 + 两套服装切换，保存到账号，刷新后保持；切换账号互不影响。
3. 回退路径：禁用 WebGL / 模型 404 时显示静态形象；Playwright 测试覆盖这两条路径。

验收（采用你给的标准）：手机和桌面都能显示；能旋转；至少 2 种发型 + 2 套服装；保存后刷新不丢；比赛页面不加载 Three.js（用网络请求断言）；GameSim 金标不变；加载失败有静态形象；资源来源与授权写进文档。

## 4. 剩余阻塞与风险
1. **P0 隐私**：两个存档槽是设备级的，旧存档没有归属（§1.2）。My Games 上线前必须先定。
2. **反馈没有真实落点**：生产联机服务器还没部署。在部署前，Player Voice 只能做"本机保存 + 复制"，不能说"已提交"。
3. **3D 美术**：CC0 角色可能需要在 Blender 里拆出发型、服装部件；本仓库里还没有美术流程。
4. **手机性能还没测**：本机没有真机/模拟器（之前已确认没有 Android SDK 和完整 Xcode），只能先在桌面 Chromium 的移动视口里测，结论需要真机复核。
5. 本文的数字（体积、超时、限流）都是初始建议值，以 spike 实测为准。
6. B49（手机"继续生涯"按钮遮挡文字）仍然是单独的小修复，不并入以上任何工作包。

## 5. 需要你决定的问题
- **Q1 旧存档归属**：没有账号标记的旧存档，是 (a) 归给当前登录账号一次并写上标记，(b) 只在游客模式显示，还是 (c) 显示为"本机存档（未关联账号）"，让玩家自己认领？我建议 (c)。
- **Q2 反馈后端**：选方案 A（扩展现有服务器）吗？生产服务器部署时间和域名是否已有计划？
- **Q3 3D 美术**：垂直切片先用 Quaternius 的 CC0 角色可以吗？还是你有指定的美术风格/外包？
- **Q4 体积预算**：My World 首次打开允许额外下载多少（建议 ≤ 1.5 MB，含 Three.js 和模型）？
- **Q5 执行顺序**：建议 N-1d（先修隐私缺口）→ N-1e 的 UI 部分（角落入口 + 本机队列）→ N-1f spike。这样可以吗？

## 实现状态：Q1 存档归属 + My Games（R169，已实现）

- **做法**：独立元数据键 `cls_save_owners_v1`（`js/data/saveOwnership.js`），**不改**任何存档的格式。条目 `{ owner, sig }`：owner 是账号 id / `guest` / `null`（`null` = 归属功能出现之前的旧存档，即"本机存档·未关联账号"）。
- **规则**：已存在但没有条目的存档，启动时一律标为未关联，从不自动归给当前账号；同一份生涯再次写入保持原 owner，只有新生涯才归当前玩家；中途进度槽没有实例 id，只有在本页通过「继续」恢复时才保留原 owner。认领必须玩家显式确认（确认框写明"认领只管理归属，不能证明你就是原主人"），取消不改任何东西；已被认领的存档不能再被认领；游客不能认领；认领失败或存储失败不删除存档。
- **可见性**：别的账号的存档不进 My Games，也不出现在首页「继续」条和赛季设置页的恢复入口；切换账号立即刷新。未关联存档对所有人可见（带标签），登录账号可认领。
- **My Games**：列出玩家可见的生涯存档和中途进度（两个设备级槽位，今天最多两行）。已结束的历史记录不在本次范围。
- **验证**：`tests/saveOwnership.test.js` + 浏览器 `scripts/qa/save-ownership.mjs` 48/48（桌面+手机：A/B/游客隔离、旧存档未关联、取消/确认、认领后 A 不能再认领、游客只能看不能认领、存档始终未删除、英文无中文、无溢出、对比度）。变异验证：把 `saveVisibility` 改成永远返回"mine"，QA 在桌面和手机各有 5～6 项变红。
- **已知限制**：同一浏览器里的账号可以认领任何未关联存档；这只是归属管理，不是身份证明。账号 B 开始新生涯会覆盖单槽位里 A 的生涯（既有的单槽位设计，开始新生涯前原本就有覆盖确认）。
