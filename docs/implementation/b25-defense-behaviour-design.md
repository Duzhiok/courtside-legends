# B25 设计：`switch_all` / `zone_drop` 的真实防守行为（**已实现，见 §7**）

> 日期 2026-11-22 · owner Code Puppy · 依赖 B23（已完成）· §1–§6 是实现前写的设计与实测；用户 2026-11-22 要求“按推荐逐步进行”，Q1–Q3 按推荐执行，结果在 §7。
> 关联：`tactics-pnr-roles-design.md` §8（幽灵跑位 / 假掩护现在没有对手可以“骗”）。

## 1. 现状（实测，不是推测）

**一支队只有一个 `tactic`，攻守共用。** `switch_all` 和 `zone_drop` 同时是这支队的进攻体系：进攻乘数 0.99 / 0.98，换来防守乘数 1.10 / 1.08
（`zone_drop` 还把己方三分权重抬高 1.05）。它们在引擎里**只有这些乘数**（`def.tactic.defense` 在 `sim.js` 只出现 3 处：1030 / 4499 / 4718），
战术自己的 `desc` 也承认“换防本身没有单独逻辑”“放中距离、怕底角没有对应实现”（`js/data/coaches.js` 204–230）。
对照：`pack_paint` 是唯一有真行为的防守战术（`packPaint` 标志，`sim.js` 里 5 处引用），它是现成的写法样板。

**探针** `scripts/measure/defense-tactic-vs-action.mjs`：同种子，主队全员打同一个动作，只改客队战术；200 场 / 格，公牛 96 vs 超音速 96，主队场均得分：

| 客队防守战术 | 全员挡拆 | 全员单打 |
|---|---|---|
| 均衡（基线） | 110.1 | 95.9 |
| 收缩篮下 `pack_paint` | 107.3（−2.8） | 90.7（−5.2） |
| 沉退联防 `zone_drop` | 106.0（−4.0） | 90.1（−5.8） |
| 无限换防 `switch_all` | 107.5（−2.5） | 91.9（−4.0） |

读法：
1. **三种防守战术都是对单打压得比对挡拆更狠**，和篮球直觉相反：换防本该克制挡拆（掩护被抵消），沉退本该克制下顺、放弃中投拉起。现在没有任何一条跟“进攻在打什么”有关。
2. 挡拆本身比单打高 **+14 分 / 场**（110.1 vs 95.9，同一支球队）。这是进攻方的 `scheme` 加成（`calcOpenness` 里的分球射手 +0.085、持球中投口袋 +0.055、滚下窗口 +0.04、`pnr_master` +0.05，`calcMakeProb` 里的 +0.045 / +0.05 / +0.03……；注：`pnrBump` 1.08 是体能消耗系数，不是传球权重，初稿误列），
   防守战术没有任何一项去抵消它。这既是 B25 的空间，也说明 B26 / 挡拆校准要一起看（见 §6）。
3. 上一轮的教训：探针里必须用 `markOrdersManual`，直接写 `p.orders.action` 会被引擎按推荐值重算（我的 `pnr-roles-ab.mjs` 就因此错过，已更正）。

## 2. 目标与边界

- 让这两个战术**针对挡拆 / 传切**产生真实、可测、可解释的差别，而不是一个均匀乘数。
- 复用引擎已有旋钮（开放度、传球权重、命中修正、`bigMismatch`），**不抽新随机数**，只对 `def.tactic.id` 命中的回合改乘数。
- 其它战术、`balanced` 防守：**逐字节等于现在**（同 §8 “零回归”的做法）。
- 不做：把战术拆成独立“防守姿态”入口（见 §5 Q1）；不动 `pack_paint`；不动 UI 结构。

## 3. 提议的行为（数值待测，结构先定）

只在进攻 `sideCtx.scheme` 是 `pnr` / `drive_kick` 的回合生效，进攻是单打 / 低位 / 无球定点时不变。

**`switch_all`（无限换防）——抵消掩护，惩罚错配**
- 掩护的好处打折：滚下窗口 +0.04、分球射手 +0.085、中投口袋 +0.055、`pnr_master` +0.05，以及命中里对应的 +0.045 / +0.05 / +0.03 这类“因为有掩护才有”的项 × `switchScreenKeep`（初值 0.5）。
- 换防造成错配：沿用现成的 `bigMismatch`（`sim.js` 4697，命中率里的错配项，今天只看“大个子防小个子 / 小个子防大个子”的体型差）。换防回合里把它按换防比例放大，而不是新造一套；终结权重不动。
- **`slip` / `ghost` 因此有了真实用途**：它们本来就不依赖掩护，所以对 `switch_all` 的回合**保留**自己的开放度（`slipOpen` 0.06），而 `roll` / `pop` 被打折。
  这是“幽灵跑位只对换防有意义”这句话唯一站得住的版本，而且是可测的。

**`zone_drop`（沉退）——保篮下、让中投、怕底角**（正是它自己描述承诺的）
- 篮下：滚下终结与篮下命中小幅下降、盖帽略升（量级低于 `pack_paint` 的 −0.07，避免重复叠加）。
- 中距离：挡拆持球人的中投 `open` 上升（`finish: mid` 因此值钱）。
- 底角：分球给底角射手的 `open` 上升（描述里的“怕底角”）。
- 单打 / 无球不变。

**平衡补偿：** 新行为只落在挡拆回合，所以均匀的防守乘数（1.10 / 1.08）要相应下调，使“默认 CPU 战术混合”下的联盟平均不变（见 §4 A4）。

## 4. 验收（先写死，再调数）

- A1 `balanced` 防守、其它战术：同种子比分与全队技术统计与 main 逐项一致（金标只允许 `switch_all` / `zone_drop` 相关种子变化）。
- A2 `switch_all`：对挡拆的压制 **大于** 对单打的压制（今天是反的，见 §1）；`pnr + slip/ghost` 的得分 **不低于** `pnr + roll`。
- A3 `zone_drop`：挡拆持球人的中距离出手占比上升，篮下命中率下降；单打不比今天更差。
- A4 联盟校准（`gamesim-calibration.mjs --compare`）在现有带宽内；CPU 教练有 5 个把 `switch_all` 放进 `specialTactics`，这是最大的漂移风险。
- A5 `desc` 里“尚未实现”的两句改成真实行为（中英），`tests/i18n*` 钉子同步。
- 每条验收用**探针**证明，不靠单测里的统计断言（遵守“别为次要指标调测试”）。

## 5. 需要你拍板的三件事

- **Q1：做在现有战术里（推荐），还是拆成独立的“防守姿态”入口？** 根因是一个 `tactic` 攻守共用；真拆是 L4 + 战术板结构大改，收益是“进攻体系和防守姿态各选各的”。
  推荐先做在现有战术里（L3，一个文件两三处读取点），拆分另开一条。
- **Q2：同意 `slip` / `ghost` 成为对 `switch_all` 的答案吗？** 这决定它们在产品里是不是“有用的选择”，而不只是中性选项。推荐同意。
- **Q3：允许下调均匀防守乘数来补偿吗？** 不补偿就是给这两个战术白加强；补偿就会改变它们对**非挡拆**进攻的表现（会变得没那么强）。推荐补偿，目标是联盟平均不变。

## 6. 顺带发现（不在 B25 范围，只记录）

- 挡拆比单打高 14 分 / 场（§1 读法 2）。真实 NBA 里挡拆是效率最高的动作，但这个量级值得单独问一句是不是过强；它和 B26（追分 / 快节奏固定系数）、B35（出手分配）共用 `scheme` 加成。**没有动。**
- 引擎没有“包夹挡拆持球人”的行为（`defensePlan.scheme === "double"` 只加权球权，见 `sim.js` 4054）。如果以后要让包夹也针对挡拆，是 B25 之后的第二步。

## 7. 已实现（Code Puppy，2026-11-22）

按推荐：Q1 做在现有战术里；Q2 假掩护/幽灵是换防的答案；Q3 补偿均匀乘数。

**代码**：`js/engine/defenseCoverage.js`（纯函数，无随机数）+ `sim.js` 里 9 处“常数 × `keep`”/加一项。`keep` 对其它防守恒为 1，所以数值逐位不变。
`zone_drop.defense` 1.08 → **1.04**（补偿）；`switch_all` 保持 1.10（自然订单下它没有漂移）。两个战术的 `desc`（中英）改成真实行为。

**验收（`defense-tactic-vs-action.mjs`，3 组对阵 × 150 场 / 格，客队战术之外同种子）：**

| | 改前 | 改后 |
|---|---|---|
| A1 `balanced` / `pack_paint`，三种动作共 6 格 | — | **与改前逐位相同** |
| A1 联盟校准 JSON（6 个年代 × 12 场，默认战术） | — | **逐字节相同** |
| 沉退 对挡拆 / 对单打（Δ vs 均衡） | −5.1 / −5.1 | **−6.4 / −3.2** |
| 换防 对挡拆 / 对单打 | −3.5 / −3.7 | **−5.9 / −3.7** |
| A4 自然订单 沉退 / 换防 | −4.9 / −2.9 | **−4.9 / −2.9**（补偿到位） |

- A2 前半成立：两个战术现在都是对挡拆压得比对单打狠（之前是反的）。
- A2 后半**部分成立**（`pnr-roles-ab.mjs` + `AWAY_TACTIC=switch_all`，150 / 120 场）：对换防，**假掩护两队都不低于下顺**（公牛 +0.3，湖人 +0.6）。
  **幽灵取决于掩护人**：公牛（朗利不是顺下威胁）幽灵比下顺高 +2.5，湖人（奥尼尔）低 1.9——换防把后卫换到奥尼尔身上本来就是送礼，所以湖人该打真掩护。
  这符合篮球，不是 bug，所以没有为凑数继续调 `switchGhostOpen`（取 0.06，与 `slipOpen` 同值：都是把被换防的人甩在身后）。
- A3 未单独做“中距离出手占比”探针：沉退对挡拆的 FG% 由 53.4 → 52.3、自然订单 51.1 → 51.2（补偿后），方向是对的，但这条我只有 FG%，没有出手分布，**不声称已验证**。
- A5 `desc` 已改，`tests/tacticGroups.test.js` 的 B21 钉子改成 B25：不再自称“没实现”，并写明真实行为；`zone_drop.defense` 钉子随补偿改到 1.04 并写明原因。
- 单测 `tests/defenseCoverage.test.js` 9 条，3 个变异（换防不抵消 / 沉退不护框 / 假掩护也被抵消）全部被抓到。

**局限 / 没做**：
- `bigMismatch` 放大（`switchBigOnGuard` 1.6）和 `dropBlockMult` 在这个探针里看不出单独贡献，数值是首版猜测，没有单独标定。
- 联盟里有 CPU 教练把 `switch_all` 放进 `specialTactics`：校准 JSON 用默认战术所以没碰到它们；自然订单探针（3 组对阵）显示不漂移，但没有跑完整赛季级别的联盟模拟。
- 挡拆比单打高 14 分的问题没动（§6）。
