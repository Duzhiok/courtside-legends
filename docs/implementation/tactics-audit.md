## 1. 一句话结论
战术**不是太少，是一个槽位塞了四种不同的东西**；引擎里其实已经有分层（战术 → 回合重点 → 节奏 → 防守计划 → 追分脚本），**缺的是 UI 按这个结构呈现，以及清掉几处叠加**。

## 2. 对「战术合理性」那张表的核对
| 说法 | 代码核对 | 结论 |
|---|---|---|
| 收缩篮下其实是防守术语 | `pack_paint` 数据里四个乘数全是 1，注释写明 `Defensive stance, not a system: the sim reads this flag, never the flat multipliers`；只在 `sim.js` 里改防守方的篮下命中（-0.07）、盖帽和分球后的空位（+0.08）| **成立** |

## 4. 叠加 / 重复来源（需要设计决策，我没有判定为 bug）
1. **`crash_boards` / `second_chance` 的进攻篮板**：数据 `orbBoost`（0.07 / 0.05，`sim.js:3118`）**加上** 按 id 写死的 `+0.025`（`3120`）。同一战术两条加成来源，合计 0.095 / 0.075。
2. **禁区权重**：`second_chance` 的 `paintBias 1.35`（`3940`）**再乘** id 分支 `×1.12`（`3945`），合计约 1.51；`crash_boards` 只有 id 分支 ×1.12。
3. **三分压低两次**（同一战术数据里的 threeRate 与代码里的 paintBias/id 分支各压一次）：`paint_attack` 的 threeRate 0.72 **且** `paintBias>1` 分支再对三分乘 `max(0.55, 1.15−paintBias×0.25)`；`twin_towers` 的 threeRate 0.78 **且** id 分支再乘 0.82。
4. （观察，不算叠加）`post_up / twin_towers / paint_attack / crash_boards / second_chance` 共用 `chemistry.js:181-190` 同一个 `if` 块：≥2 个 C/PF +5、1 个 +2；`twin_towers` 另有「≥3 个空间型球员 −3」。五个战术在阵容适配上完全同质。
