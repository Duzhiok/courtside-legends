# ADR-007：传奇宇宙（未来新秀用真实人物）+ 四分线规则事件 + 2050 终局与终身勋章

- **状态**：✅ **APPROVED WITH MODIFICATIONS**（产品负责人 2026-11-06 审批；修改项见 §0.1，已并入正文）。仍为 OPEN 的只有 Q3（头条名额）和 Q6（跨界授权），见 §8。**纯规划，不改 GameSim、历史数据、存档结构、账号系统。**
- **输入**：产品负责人 2026-11-06 的原始想法（见 `DECISIONS.md` §六 原话要点），以及一份外部 AI 起草的方案。本文把那份方案和仓库现状逐条对照，保留对的，改掉错的。
- **在路线图里的位置**：不新建里程碑。映射见 §7。

## 0. 已认可的方向（不再重问）

1. 不用凭空捏造的人物填未来选秀。
2. 未来新秀优先来自真实人物：没进过 NBA 的国际传奇、NBA 成立前的先驱、跨时代重生的 NBA 球员；跨界名人（其他运动、娱乐明星）作为可选内容。
3. 模拟最多到 2050：最后一个完整赛季是 2049–50，结算后进入终局。
4. 生涯结束拿终身荣誉勋章，挂在账户首页。

**一条澄清**：玩家**自己**捏的人物（ADR-005 的原创穿越 / 随机命运里的"你"）不算"捏造 NPC"，不受规则 1 限制。规则 1 管的是联盟里的其他球员。

## 0.1 产品负责人批示（2026-11-06，本文正文已按此修改）

1. 未来球员的**主要来源**是策展的真实人物；NBA 跨时代重生允许，并用来撑住未来选秀，但**不是无限重复**。
2. **每个真实人物在同一条时间线里最多重生一次**。
3. 同一时间线里，一个人**不能同时有两个活跃实例**；原有职业实例退出联盟后才能重生。
4. 重生者从**符合年龄的新秀档案**起步，不直接复制巅峰 OVR。
5. 真实职业轨迹是**成长参考，不是命运上限**：必须允许与历史不同的结局。（**否决**本文初稿"用 `historicalLadder` 封顶"。）
6. 历史传奇宇宙：重生**低频**；全明星幻想宇宙：可以**高频**。
7. **Original Reborn 保留，定义改为"玩家自己创建的角色进入历史联盟"**，不是系统随机编一个陌生球员。
8. 新增独立选项 **Legendary Reborn**：穿越成为国际篮球传奇或历史先驱。
9. 实现前先做**候选池容量模拟**（已做，见 §10）。
10. 最后一个可玩赛季 2049–50；提前的主动退休与正常退休照常支持。区分 **Career Retirement**（某个职业身份结束）和 **Lifetime Finale**（整段 Reborn 人生结束）；终身勋章在 Lifetime Finale 幂等发放，单个职业阶段结束发对应职业成就章。
11. 四分线仍是独立的 GameSim 里程碑；2035 启用只是**可配置的起始假设**，不是已确认的现实 NBA 规则。
12. 不要现在实现：未来选秀生成器、四分线、托管联赛。

## 2. 对外部方案的修正（最重要的三条）

### 2.1 人数：主力来源必须是"NBA 球员跨时代重生"，而且默认开启

外部方案把"NBA 传奇跨时代重生"放在优先级第 4、并在历史宇宙里标成"可选"。按上面的数，这样会不够用：

- 国际传奇 + 先驱 + 跨界名人，靠人工整理，现实上是**几十到几百人**；
- 需求是 **1,440–1,800 人**。

真实 NBA 球员重生正好补上这个缺口：4,393 人都有完整数据，能直接走现有的 `seasonToCard` 进 GameSim；用的也是游戏里本来就在用的 NBA 球员姓名，没有新增授权问题。

**建议**：
- 重生是**主力**（大多数新秀），国际传奇 / 先驱 / 跨界名人是**亮点**（每届几个头条新秀）。
- 重生在两个宇宙里都开，但**频率不同**：历史宇宙低频（头条名额小、主要补人数），幻想宇宙高频。受 §2.2 的"每人一次"约束，所以不会出现"每隔几年就有一个科比"。
- 人物池耗尽时：先缩小选秀规模，再从重生池补自由球员。**永不回退到 `generatedProspect`**。保留它只为读旧存档里已经存在的虚构球员。

### 2.2 重生规则（产品负责人 2026-11-06 修改后）

- **每人一次**：同一条时间线里，一个真实人物最多重生一次。重生后他的 `personId` 进入"已重生"集合，之后不再进入任何候选名单。
- **不同时活跃**：他在本时间线的原有职业实例必须已经退出联盟才能重生；开局前就退役的人直接可选。**不再要求固定冷却年数**（初稿的 N=10 年作废）；`cooldown` 保留为可配置项，默认 0。容量模拟显示 N 从 0 到 10 对结果几乎没影响（§10），所以不值得作为产品规则。
- **起点**：用他**真实新秀年**那张卡（样本不足时取第一个"场次/分钟够"的赛季），年龄重置为 19–22，**不用巅峰卡**。
- **成长不被历史封顶**：真实轨迹是**参考先验**，不是上限。重生者可以比真实的自己更差，也可以更好。这是玩家"改写历史"意义的一部分。
  - 代价要老实写：现在的 `historicalLadder` 上限就是为防止成长失控，没有它就必须有别的护栏。**落地时必须单独设计**：潜力/上限怎么给（建议：参考真实巅峰作为期望值，加上有界随机偏离）、全局 OVR 封顶怎么处理（DECISIONS D5 OVR 99 vs 传奇 100 仍为 OPEN）、`playerGrowth.js` 的年龄成长表是否够用。不在本 ADR 里拍数字。
  - 不允许新增"只写不读"的潜力字段；任何新属性必须有 gameplay 读取点。
- **身份与实例分开**：`personId`（真实人物）≠ `instanceId`（本时间线里的这一段生涯）。历史数据只读，重生后的交易、伤病、荣誉都记在实例上。

### 2.3 谁真的会打到 2050

外部方案的终局写法默认"人人打到 2050"。按现有规则：

- 1996 年入行的教练 2031 年 70 岁强制退休；
- 1996 年 22 岁的球员大约 2014 年前后退役；
- 真会撞上 2050 的主要是**联盟经理（Franchise）**和**晚开局**（比如 2020 年开局）的生涯。

所以终身勋章必须在**任何合法生涯结束时**发放（主动退休、正常退休、2050 终局三种），2050 只是兜底。这一点外部方案提到了，但要升级成验收条件。

## 3. 人物池设计：传奇候选登记表（Legendary Candidate Registry）

不新建球员引擎。新增一张只读登记表 + 一个资格判定函数，挂在现有选秀管线前面。

```
roster.json（只读）  ──┐
策展人物表（只读，新） ──┼─> 资格判定 eligibleCandidates(timeline, year) ─> rookieClassForYear（现有）─> 现有选秀/成长/退役
时间线实例表（存档里） ──┘
```

**每届选秀的取人顺序**（第 1 级最先）：

1. 当年真实首秀、本时间线里还没出现过的人（2025 年前才有）；
2. 头条名额（每届上限，建议 2–4 人）：非 NBA 国际传奇 → 先驱；
3. NBA 跨时代重生（主力，按 §2.2 的规则）；
4. 跨界名人：只在幻想宇宙，单独的"跨界选秀"名额，不占正常顺位。

**每个策展人物的必备字段**（字段名是建议，不是现有 schema）：`personId`、`category`、`historicalNBAExperience`、`sourceEvidence`（篮球履历出处 + 属性估算方法）、`rightsStatus`（`unreviewed` / `cleared` / `blocked`）、`universe`（historical / fantasy）。**没有出处的人不进表；`rightsStatus ≠ cleared` 的人不进公开发布版本。**

**类别边界**：
- 先驱：严格指没打过 NBA 正式比赛的人（例如 NBA 成立前的球员）。打过 NBA 的早期球星（如 Mikan）归"重生"，不归先驱。外部方案自己也指出了这个区别。
- 跨界运动员：只有身体素质给初始优势（速度、爆发、耐力），投篮、控球等篮球专项从低位起步，靠成长系统学。
- 娱乐明星：不进历史宇宙。在幻想宇宙里，进正式选秀也要玩家建档时手动打开。

## 4. 两个宇宙（建档时选，存档内不可切换）

| | 历史传奇宇宙（默认） | 全明星幻想宇宙 |
|---|---|---|
| 真实 NBA 球员 / 重生（每人最多一次） | ✅ **低频** | ✅ **高频** |
| 非 NBA 国际传奇、先驱 | ✅ | ✅ |
| 其他运动明星、娱乐明星 | ❌ | ✅（跨界名额；进正式选秀需手动开） |
| 四分线 | 可配置 | 可配置 |
| 2050 终局 | ✅ | ✅ |

同一个 GameSim、同一套赛季流程，区别只在候选池配置和联盟规则。

## 5. 四分线：联盟规则事件

- **形式**：存档内的联盟规则（建档时定、季中不可改），到启用年份在休赛期作为"联盟大事件"生效并写进新闻。
- **可配置的起始假设**：2035 年启用、30 英尺、允许关闭。这是游戏设定，**不是已确认的现实 NBA 规则**，界面上要写明。
- **硬约束**：关闭时比赛**逐字节不变**，用 M2b-0 的 20 个金标哈希兜底（`tests/fixtures/simGolden.json`）。
- **前置**：先把散落的规则常量集中成 `LeagueRules`（`BASELINE_AUDIT.md` §9）；四分线本身另写一份 GameSim ADR（出手区域、命中、比分、技术统计、播报、AI 追分、2D 球场），排在 M2b-1 和 M3 之后，因为它们改的是 `sim.js` 同一片代码。
- 四分能力不是三分能力换个名字：从三分 + 射程 + 抗干扰推导，再用固定种子测量校准。成长系统可加"超远射程"训练重点，复用 `FOCUS_ATTRIBUTES`。

## 6. 2050 终局与终身勋章

- **终局时点**：2049–50 赛季结算完成、进入 2050 休赛期时触发，只触发一次（幂等）。不在赛季中途截断。
- **两种"结束"分开**（产品负责人 2026-11-06）：
  - **Career Retirement**：某个职业身份退休（球员 2014 退役、教练 2031 到 70 岁、主动退休）。发**对应职业的成就章**，不结束整段人生。
  - **Lifetime Finale**：整段 Reborn 人生结束（最后一个职业退休且不再转型，或 2050 终局兜底）。发**终身章**，幂等。
  - Reborn 里职业转换（球员 → 教练 → GM）只触发前者；这样球员转教练不会重复领同一份终身奖励。GM 可以经营到 2050。
- **两层荣誉**：
  - *完成勋章*：每段合法生涯都有，包括没拿冠军的；
  - *档次*：复用 `legacy.js` 的分档，按职业各自评分（教练沿用现有公式；球员和 GM 的公式要先做模拟分布再定阈值，不现在拍数字）；
  - *终身传奇*（图里的 "Lifetime Legend · 3 职业身份"）：一整段 Reborn 人生（可能跨多个职业）结束时发一枚总章。
- **存放**：账号层新增 `LegacyArchive`（与账号绑定，和生涯存档分开），每条记录带来源存档 id 和结束原因，`grantId` 去重保证幂等。账号首页展示，点开看生涯摘要（复用 `endingShareCard.js`）。

## 9. 验收门槛## 9. 验收门槛（实现时必须有的测试）

1. **人物池耗尽模拟**：从 1996 开局一路模拟到 2050，每届新人数 ≥ 退役人数，每队名单 ≥ 最低人数，全程**零个**虚构球员。**静态容量部分已做（§10）**；实现时还要用真实选秀管线和 `GameSim` 再跑一次端到端版本。
2. 同一时间线不出现同一人物的两个活跃实例。
3. 每个新人物都有 GameSim 需要的完整属性（复用 `seasonToCard` 的校验）。
4. 四分线关闭时 20/20 金标哈希不变。
5. 2049–50 赛季完整结束；终局只结算一次；勋章重复发放被去重。
6. 删除生涯存档、换账号再切回、开新生涯后，勋章仍在。
7. 旧存档（含已存在的虚构新秀）照常读取。
8. **每人最多重生一次**；已重生的人不再进入任何候选名单；原实例未退出时不可重生。
9. 重生者起点是新秀档案（年龄 19–22、OVR 不等于其巅峰），**且成长不被 `historicalLadder` 封顶**（用固定种子构造一个成长结果超过真实后续卡的例子）。
10. Career Retirement 与 Lifetime Finale 分开：球员退役转教练只发职业章，不发终身章；终身章对同一 `grantId` 只发一次。
11. 位置配额：按位置分组的候选池耗尽测试（§10 的中锋瓶颈）。

## 10. 候选池容量分析（已做，2026-11-06）

脚本：`scripts/research/rebirth-capacity.mjs`（只读 `roster.json` + `seasonToCard`，不改任何引擎代码）。
规则：每人一次；原实例必须已结束（2025 年仍在打的人假设再打 6 年）；新秀档案 = 第一个 `gp ≥ 15 且 mpg ≥ 8` 的赛季；24 届（2026–2049）；头条（peak OVR ≥ 80）每届上限 2 或 4，其余是 peak < 80 的人。

| 项 | 结果 |
|---|---|
| 真实人物 | 4,393 |
