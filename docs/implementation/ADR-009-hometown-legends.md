# ADR-009：Hometown Legends（家乡传奇）— 地点驱动的个性化

状态：**PROPOSED，仅规划。** 未经评审不改代码。日期：2026-11-06。

## 1. 结论先行

做成**横向能力**，不是第五个模式：一条通用链路「地点 → 有来源的真实人物关系 → 个人故事 → 现有 GameSim 挑战 → 长期荣誉」。不为任何城市写专属玩法。MVP 只做策展小集合，其余走逐级回退。

## 2. 核实过的现状（决定设计的三个事实）

| 事实 | 证据 | 后果 |
|---|---|---|
| **球员数据里没有任何地点信息** | `roster.json` 全部字段：`bref,name,season,team,pos,gp,mpg,ppg,rpg,apg,spg,bpg,tpg,fg,tp,ft,fga,tpa,src,id,slug`；4393 人，无出生地/国籍/大学 | 关系表必须**新建并策展**；`team` 是效力球队，只能当 `TEAM_LEGACY` 的线索，**绝不能推出出生地** |
| 人物有稳定主键 | `bref`（4393 个唯一）；ADR-007 也要求统一 `personId` | 关系表只引用 `bref`，不复制球员数据 |
| My World 的"家乡"现在是**自由文本** | `js/data/profile.js`：`profile.hometown`（≤40 字，刚上线） | 结构化地点要**另开字段**，旧文本不迁移、不覆盖，作为展示名保留 |

另：账号身份与 Reborn 职业身份分离是已批准规则（ADR-006/008），本 ADR 不改。

## 3. 三个地点身份，互相独立

| 字段 | 含义 | 影响 | 性质 |
|---|---|---|---|
| `birth` | 出生地 | 出生地传奇、个人故事、家乡勋章 | 自述 |
| `raised[]` | 成长地（可多个） | 偶像/导师候选、剧情模板 | 自述 |
| `represented` | 代表城市 | 城市荣誉、主场展示、挑战归属 | 自述，可与前两者不同 |

当前居住地**不做**（MVP 范围外，且涉及隐私）。**自选而非 GPS**：不请求定位权限，不收集真实住址；最细粒度到城市。三项都允许留空，留空不影响任何其他功能。

## 4. 数据契约（建议，评审后定稿）

三张表，全部是静态数据文件，不进存档（存档只存 ID）：

```js
// js/data/hometown/locations.js —— 策展小集合 + 回退链所需的层级
{ id: "CN-SH-SHANGHAI", level: "city", parentId: "CN-SH", names: { zh: "上海", en: "Shanghai" } }
{ id: "CN-SH", level: "region", parentId: "CN", names: {...} }
{ id: "CN", level: "country", parentId: null, names: {...} }

// js/data/hometown/legendLocations.js —— 一条记录 = 一个有来源的断言
{ bref: "yaomi01", locationId: "CN-SH-SHANGHAI", relation: "BIRTHPLACE",
  source: { type: "reference", ref: "<可复核的出处>", checkedOn: "YYYY-MM-DD" } }

// 账号侧（account.origin，新字段，可缺省）
{ birthLocationId, raisedLocationIds: [], representedLocationId, idolBref }
```

- `relation` 枚举：`BIRTHPLACE` / `RAISED_IN` / `TEAM_LEGACY`；以后加类型需走评审。
- `source.type`：`reference`（已核实）| `community`（社区提名，**默认不展示**，审核通过才升为 `reference`）。
- 一个人物可有多条记录；**每条必须带来源**，缺来源的记录加载时丢弃并计入校验失败。
- 不允许把一个球员"挂"在没有记录的城市；回退只能降层级，不能编造。

## 5. 来源核验规则（硬规则）

1. 每条关系必须有可复核出处和核验日期；**不得**由姓名、国籍、球队所在地推断。
2. `TEAM_LEGACY` 只能表示"效力过该城市球队"，UI 文案必须写成"效力"，不得写成"家乡球星"。
3. 一个球员可同属多个地点，但 UI 要显示**为什么**（出生 / 成长 / 效力），三种标签文案不同。
4. 回退时 UI 必须标明层级：「本市传奇 / 本州（省）传奇 / 本国传奇 / 你自选的偶像」，不得把外地人物说成本地出生。
5. 加载校验：`bref` 必须存在于名册；`locationId` 必须存在于地点表；关系类型在枚举内；重复记录去重。测试里把这些做成断言。
6. 公开发布前，人物姓名/照片的授权审查与 ADR-007 一致，不因"有地点关系"而豁免。

## 6. 逐级回退（小城市公平性）

`city → region → country → 玩家自选偶像`。每一级有结果就停；全部无结果时给"自选偶像"入口，**任何地点都不会出现空页面**。小城市玩家和大城市玩家都能完成同一套 H1–H5 流程，只是候选来源不同。MVP 不做全球城市库：玩家可输入未收录城市，按"国家 + 自由文本城市名"保存，回退到国家级。

## 7. 与四个空间的关系

| 空间 | MVP 体现 | 以后 |
|---|---|---|
| My World | 出生/成长/代表城市、家乡传奇卡、偶像、家乡挑战结果、家乡荣誉 | 城市旗帜、球衣、家园装饰 |
| My Team | 不改（见 §8） | 城市主题收藏（纯展示） |
| Career（Reborn） | 不改；人物关系表仅供 ADR-007 复用 | 家乡开局、导师、荣归故里 |
| Playground | 家乡挑战（现有 GameSim） | 地域对抗阵容自动生成 |

## 8. 不做什么（与你的设计约束一致）

- **不因出生地送强力卡**。奖励只给故事、勋章、纯外观；卡牌仍走 My Team 现有获取规则。
- 不新增竞技属性（没有消费者的字段不加）。
- 不做地点排行榜、实时社交、全球城市库、青少年篮球系统、导师 AI。
- 不改 `GameSim`，不引入第二套模拟。
- 不改存档版本以外的东西：`account.origin` 可缺省，旧账号零迁移。
- Reborn 人物的家乡属于各自职业存档，不读写 `account.origin`。

## 9. MVP 用户流程（H1–H5）

1. **H1 选地点**：My World → 编辑身份 → 三个选择器（出生 / 成长 / 代表）。输入城市或从策展列表选；可跳过。
2. **H2 家乡传奇卡**：按 §6 回退取候选，显示 ≤3 位，每位带关系标签（出生/成长/效力）和层级标签；空则显示自选入口。
3. **H3 童年偶像**：从候选或全名册搜索任选一位（偶像不受时间线限制）；存 `idolBref`。偶像 ≠ 导师：导师需满足时间线条件，属后续阶段。
4. **H4 家乡挑战**：Playground 里一场"你的代表城市传奇阵 vs 随机历史强队"，阵容由 §4 关系表自动生成，直接用现有 `GameSim`；结果写入 My World 荣誉。关系表不足 5 人时用回退层级补齐，仍不足则隐藏该挑战（不造人）。
5. **H5 家乡荣誉**：My World 展示出生/成长/代表三行、偶像、家乡挑战战绩。空状态如实。

文案全部中英双语；英文界面不得出现中文残留（沿用现有测试手法）。

## 10. 代表性测试夹具（评审时核对，不预先声明为事实）

夹具用**假的测试数据**验证机制，不依赖真实人物断言：

| 夹具 | 验证点 |
|---|---|
| 同一人物 3 条关系（出生/成长/效力）分属 3 个城市 | UI 三种标签文案各不相同；排序稳定 |
| 只有 `TEAM_LEGACY` 的城市 | 文案是"效力"，**不出现"家乡/出生"** |
| 城市无记录、省有记录 | 回退到省，层级标签写"本省" |
| 城市、省都无，国家有 | 回退到国家 |
| 全都无 | 出现自选偶像入口，页面不空 |
| 记录缺 `source` / 未知 `bref` / 未知 `locationId` | 加载时丢弃并计数，不崩溃 |
| 玩家输入未收录城市 | 保存为国家 + 自由文本，不创建地点记录 |
| 旧账号无 `origin` | 读取不报错，My World 仍可渲染 |
| 出生地选择 | 账号**不增加任何卡牌或金币**（防"选城市拿强卡"回归） |
| Reborn 存档存在 | 改 `account.origin` 不读写职业存档 |

真实人物条目（如姚明、勒布朗、诺维茨基、科比）在策展阶段逐条核实出处后才入库；上面几位只是你提出的示例，**这里没有把它们当作已核实数据**。

## 12. 待你拍板的问题

1. **策展范围**：MVP 先收多少个国家/城市？我建议先 10–15 个、每个 ≤3 位人物，质量优先于数量。
2. **代表城市可否随时改**？建议可改，不惩罚；荣誉记录按"当时的代表城市"保存，不回溯改写。
3. **社区提名**：MVP 不做，只在契约里预留 `source.type: "community"`；同意吗？
4. **偶像是否影响比赛**？建议**不影响**（纯故事/展示）；若要加成必须先有明确的竞技消费者并另议。
5. **成长地允许几个**？建议最多 3 个。
6. **自由文本 `profile.hometown` 的去留**？建议保留为展示昵称式字段，不与结构化地点互相覆盖。
7. **隐私声明**：地点为玩家自述，最细到城市，不收集住址、不请求定位。是否需要在 UI 上明示这一点？建议要。
