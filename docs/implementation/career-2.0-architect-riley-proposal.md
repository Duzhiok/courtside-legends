## 1. 已核实的历史：Pat Riley 的职业时间线

> **VERIFIED HISTORY**（已核实，来源：Wikipedia "Pat Riley" 及多家报道交叉核对）。本节只陈述事实，不含玩法推断；玩法推断一律在 §2–§8 并标注 Proposed。

| 年份 | 事件 |
|---|---|
| 1967–1976 | 球员：San Diego Rockets、Los Angeles Lakers、Phoenix Suns。1972 年随湖人夺冠（球员身份）。 |
| 1979–1981 | 湖人助教。1980 年以助教身份夺冠。 |
| 1981–1990 | 湖人主教练，Showtime 时代，4 次总冠军（1982、1985、1987、1988）。 |
| 1991–1995 | 尼克斯主教练，1994 年进总决赛，1993 年最佳教练。 |
| **1995-06-15** | **以传真向尼克斯辞职，加盟迈阿密热火，同时担任球队总裁（President of Basketball Operations）与主教练，拥有篮球事务完全控制权。**这是教练 → 管理层的转职事件本尊。 |
| 1995–2003 | 热火总裁 + 主教练（双重身份第一段）。 |
| 2003 | 卸任主教练（交棒给 Stan Van Gundy），保留总裁职位。——双重身份 → 单一管理身份。 |
| 2005–2008 | 回任主教练，同时仍是总裁。**2006 年以总裁 + 主教练双重身份带队夺冠**（总决赛 0-2 落后连赢 4 场胜小牛），这是他作为主教练的第 5 冠。 |
| 2008 | 卸任主教练（交棒给 Erik Spoelstra），保留总裁职位至今。——再次回到单一管理身份。 |
| 2010–2013 | 以总裁身份运作三巨头（LeBron James、Chris Bosh 加盟），2012、2013 年以管理层身份夺冠。 |
| 至今 | 热火总裁（自 1995 年起连续任职）。“Heat Culture”（热火文化）是他任内建立的球队机构身份。 |

**可写进游戏的三个历史锚点**（事实部分）：
1. **转职是一次 offer 事件**：1995 年不是 Riley 在菜单里点了“转职”，是热火给了他总裁 + 主教练的职位与完全控制权，他辞职接受。——对应 §3 的机会事件模型。
2. **双重身份真实存在且夺冠**：2006 年的总裁 + 主教练双冠，证明 GM+Coach 不是幻想玩法。——对应 §2 的 Architect 身份。
3. **双重身份是可逆的**：2003 年交棒、2005 年回任、2008 年再交棒。Riley 在双重与单一之间走了三趟。——对应 §3 的可逆转职。
4. **他是第一位以球员、助教、主教练、管理层四种身份都拿过总冠军的北美体育人物**（1972 球员、1980 助教、1982/85/87/88/2006 主教练、2006/2012/2013 管理层；2006 年同时计入教练与管理层）。——对应“长期目标不只是夺冠”的叙事。

**Riley 解释不了的部分**（同样是事实，用来划边界）：Riley 从未成为球队老板、从未持有股权。From Employee to Empire 的后段（小股东 → 控股老板 → 商业帝国）需要**其他历史案例**支撑，Riley 不能一套用到尾（§8）。

## 2. 四分法：Architect 身份 / 称号 / 解锁 / 风险（Proposed）

用户定稿的区分。现状问题：目前的描述（“完成教练生涯 + 完成 GM 生涯”）读起来更像成就系统，而不是一个可玩的职业身份。

| 概念 | 设计（Proposed） |
|---|---|
| **Architect 身份** | 玩家**同时拥有管理层与执教权限**的可玩职业身份。权限见 §4（ADR-006 矩阵的 GM_COACH 列）。身份是“你现在是什么人”，不是奖牌。 |
| **Architect 称号** | 玩家完成**长期王朝建设**后获得的荣誉（legacy achievement / title），展示在 My World 荣誉墙与 Legacy Museum。称号是“你做过什么”，不是入场券。现有中文名 王朝缔造者 属于称号层（见 §9 Q5 的命名冲突未决事项）。 |
| **Architect 解锁** | 进入该身份的条件，**两条路径并存**（§2.1）：(a) 经典路径（已实现，不变）；(b) 稀有职业机会事件（Proposed，§3）。 |
| **Architect 风险** | 双重身份的代价（Proposed，数值待定，§7）：权力冲突、老板干预、更衣室压力、成绩责任、工作负荷。双职不是“超级版”，与 `career-role-permissions.md` 的结论一致。 |

### 2.1 两条解锁路径并存（Proposed）

- **(a) 经典路径（已实现，不变）**：账号完成一段完整教练生涯 + 一段完整 GM 生涯（正式生涯终结：退休或时间线终局如 2050；单赛季不够；被解雇不算，除非正式生涯终结）→ 永久解锁 Architect 卡。`careerAchievements` 派生，不新增解锁存储。
- **(b) 稀有职业机会事件（Proposed）**：教练生涯进行中，满足 §7 的资格条件时，Career Inbox 可能收到一份**总裁 / 双重身份 offer**（事件，不是菜单项）。接受 → 按 §3 转职；拒绝 → 机会消失（可能有冷却期，数值待定）。这条路径**不要求**先打完两段完整生涯，但它是稀有的——Riley 是几十年一遇的人，游戏里也该如此。
- 两条路径互不冲突：走 (b) 提前进入双重身份的玩家，之后仍可通过 (a) 的完成记录获得称号层的进度；走 (a) 的玩家不受 (b) 影响。

## 3. 转职：结构化机会事件，可逆（Proposed）

### 3.1 原则

- **转职不是菜单切换**。每次转职都需要真实的职位机会、合同与权限变化——与 Career 2.0 的工程规则一致（事件状态驱动；决定记成结构化结果；GameSim 唯一权威）。
- **转职是可逆的职业路径**，但每一步都要重新拿到机会：
  - `Coach → GM`：接受总裁 / 总经理职位。获得交易与管理权限，**失去临场执教权**（`commandGame` / `setRotation` 收回，见 §4）。
  - `GM → GM+Coach`：获得兼任邀请（球队请你同时执教，或你主动争取并获老板批准）。重新获得两种权限。
  - `GM+Coach → GM`：卸任主教练（Riley 2003、2008 年的现实路径），保留管理权限；可聘请 AI 教练接手（委托，见 §7）。
  - `GM → Coach`：部分情况下允许（例如球队请你回任主教练，或失业后以教练身份再就业）。不是常规路径，需要明确的事件触发（§9 Q4）。
- **Player 不在本文范围**：球员 → 教练的转职是另一条线（ADR-005 体系），本文只覆盖 Coach / GM / GM+Coach 三者之间。

### 3.2 机会事件的形状（Proposed）

一次转职事件包含以下结构化字段（复用 Career Inbox 的承诺/决定记录方式，不新增事件系统）：

| 字段 | 说明 |
|---|---|
| `opportunityId` / `type` | 如 `president_offer`、`dual_role_invitation`、`return_to_bench`。 |
| `fromRole` / `toRole` | 转职前后身份（`COACH` / `GM` / `GM_COACH`）。 |
| `teamId` / `contract` | 球队、合同年限、薪资、权限条款（合同权限闭环 ADR-006 §3.4 的后续应用：offer 可附带授予，如“完全人事决定权”）。 |
| `requirements` | 资格条件（§7：声望、管理层信任、球队机会）。 |
| `costs` | 代价（§7：失去的权限、工作负荷、老板干预度）。 |
| `decision` | 接受 / 拒绝 / 谈判（谈判成功与否走现有谈判/信任系统，不新增掷骰）。 |
| `outcome` | 接受后：权限切换（§4）、`root.identity.history` 追加一条、生涯快照保留（M4-C 的快照规则：快照只在生涯创建时保存，转职不重写账户身份地点）。 |

### 3.3 失败与回退（Proposed）

- Offer 被拒绝（玩家拒绝）→ 机会消失，可能有冷却期；不惩罚。
- Offer 被撤回（球队变卦 / 老板否决）→ 事件以失败结算，记入时间线；玩家留在原身份。
- 转职后表现不佳 → 球队可收回兼任（GM+Coach → GM）、或解雇。**被解雇不是 Game Over**：进入 Career Opportunity 的失业 → 再就业流程（新球队、新身份都可能）。
- 转职本身不写存档版本号变化：身份变化走 `root.identity` 的可选字段（ADR-006 §3.2：`currentRole` + `history` 追加），旧存档缺失即经典 GM+Coach 的规则不变。

## 4. 权限：ADR-006 矩阵定义三身份的权力（已实现矩阵 + Proposed 转职语义）

转职的权限语义**直接复用** `career-role-permissions.md` 已实现的 15 项能力矩阵与 `careerGuards.js` 守卫，不新增能力项。转职 = 在操作入口处切换当前角色的权限集合。

| 能力组 | COACH | GM | GM_COACH（Architect 身份） |
|---|---|---|---|
| 临场指挥 `commandGame`、轮换 `setRotation`、球队训练 `teamTraining` / `setTrainingFocus` | ✅ | – | ✅ |
| 交易 `trade`、签约 `signFreeAgent`、裁人 `release`、选秀 `draft`、发展资源 `allocateDevelopment` | –（仅 `suggestTrade` / `suggestDraft` 建议权） | ✅ | ✅ |
| 观战 `watchGame`、签自己的雇佣合同 `signOwnContract` | ✅ | ✅ | ✅ |
| 球员专属 `takeover` / `personalTraining` | –（球员生涯专属） | – | – |

**转职时的权限变化示例**（Proposed，Riley 1995 年路径的玩法翻译）：
- `Coach → GM`（接受总裁职位）：获得 `trade` / `signFreeAgent` / `release` / `draft` / `allocateDevelopment`；失去 `commandGame` / `setRotation` / `teamTraining` / `setTrainingFocus`；保留 `suggestTrade` / `suggestDraft`（作为前教练的建议权，符合“教练只能建议”的现有规则）；比赛改为自动模拟 + 观战。
- `GM → GM+Coach`（兼任邀请）：在 GM 权限上加回教练组权限；同时承担 §7 的双职风险。
- `GM+Coach → GM`（卸任主教练）：收回教练组权限；轮换与训练委托给 AI 教练（委托机制是 ADR-006 §3.5 的后续项，数值与 AI 行为待定，§9 Q3）。

**实施约束（继承 ADR-006）**：授权检查放在命令入口（`requireCapability`），不是只藏按钮；UI 可见性与命令授权必须一致；CPU 球队操作不受玩家权限守卫影响。

## 5. 跨转职携带：声望、关系、机构信任（Proposed）

转职时什么带走、什么留下、什么重置。原则：**带走的是“人”的资产，留下的是“职位”的权力**。

| 资产 | 转职时如何处理（Proposed） |
|---|---|
| **声望（reputation）** | 带走，可跨身份折算。教练声望 → 管理层声望不是 1:1：总冠军、最佳教练等硬成就全额带走；“战术声望”部分折算（数值待定）。声望是转职资格（§7）的主要输入。 |
| **球员关系（relationships）** | 部分带走。球员信任（trust）跟人走：你执教过的球员记得你；但“主教练—球员”的日常关系在转 GM 后不再按教练规则结算，改为管理层—球员关系（合同、承诺维度）。关系数值不重置、不虚构。 |
| **管理层信任 / 老板信任（institutional trust）** | **按球队计，不跨球队携带**。Riley 的转职成立，是因为热火老板给了他完全控制权——信任是老板对“你这个人 + 这支球队”的判断。换队 → 信任重置为新球队的起点。同一球队内转职 → 信任保留并作为 §7 的批准门槛。 |
| **未来知识（futureKnowledge）** | 不变。它是玩家的知识，不是职位的属性；转职不影响可靠性衰减规则（只对因果相关预测衰减，GM Career 已定规则）。 |
| **球队文化（Team Culture，§6）** | 属于球队，不属于玩家。转职离开球队 → 文化留在原队；留在同一球队转职 → 文化继续积累。 |
| **能力值 / OVR** | 转职不改变任何球员或球队的能力值。身份是权限，不是加成。 |

## 6. Team Culture v1：长期资产，有上限，无任意加成（Proposed）

### 6.1 设计

Team Culture 是球队的持久属性，随长期决策积累，也会因换帅、交易、管理冲突而变化。v1 只追踪三个维度（用户定稿）：

| 维度 | 含义 | 影响渠道（只走已有系统，Proposed） |
|---|---|---|
| **纪律与训练（Discipline & Training）** | 球队对训练制度的接受程度 | 影响训练计划的接受度与执行效果——走现有训练/发展系统（`setTrainingFocus`、发展计划 `load`），不直接改 OVR。 |
| **球员发展（Player Development）** | 培养方向与球队吸引力 | 影响年轻球员的成长方向权重与球队对发展型球员的吸引力——走现有球员发展与自由市场/合同系统。 |
| **组织稳定性（Organizational Stability）** | 管理层、教练、球员之间的关系健康度 | 影响信任结算与关系事件的发生权重——走现有信任（trust）、关系（relationships）、承诺（promises）系统。 |

### 6.2 硬性约束（用户定稿，Proposed）

- **不直接给全队 OVR +5 或命中率 +3%。**文化的影响必须通过已有信任、发展、合同与关系系统体现。
- **需要有上限**：每个维度有 cap（数值待定，§9 Q2），防止无限叠加；高文化值的影响是边际递减的（具体曲线待定）。
- **可升可降**：换帅、核心交易、管理层冲突、连败都可能拉低对应维度；不是只涨不跌的进度条。
- **与声望的区别**：声望是“人”的资产（§5，可携带）；文化是“球队”的资产（不可携带，留在原队）。

### 6.3 提案中的字段形状（仅提案，不实施、不写 schema）

## 7. 资格、权衡、老板批准、失败结果（Proposed）

### 7.1 资格（eligibility）

稀有机会事件（§2.1 (b)）的触发条件，**数值全部待定**（§9 Q1）：

- **声望门槛**：教练声望达到高段位（如总冠军、最佳教练、多年季后赛——具体阈值待定）。Riley 1995 年的现实对照：4 冠 + 最佳教练 + 总决赛。
- **管理层信任**：目标球队的老板/管理层信任达到批准线。同一球队内转职沿用现有信任；跨球队 offer 需要对方球队的信任起点（新球队信任低 → offer 更稀有）。
- **球队机会**：目标球队确实有空缺（总裁离任、主教练空缺、老板换人等世界事件），不是凭空生成 offer。机会应与历史时间线事件挂钩（球队换帅/换管理层的真实节点优先）。

### 7.2 权衡（trade-offs）

- **双职的代价**：工作负荷、董事会压力、授权需求（把球探/训练/轮换委托给 AI）、角色冲突。这是 ADR-006 §3.5 的后续项，本文只定方向：双职强，但贵；压力机制是数值设计还是叙事压力，待定（§9 Q3）。
- **单职的代价**：`Coach → GM` 失去临场指挥权——你不能再亲自指挥比赛，只能模拟 + 观战；`GM+Coach → GM` 同理。
- **权力冲突**：老板干预（老板否决交易、指定用人）、更衣室压力（球员对双重身份的反应）、成绩责任（双职意味着战绩不佳时两份问责）。

### 7.3 老板批准（owner approval）

- 兼任与转职需要老板批准，批准度走管理层信任。信任不够 → offer 不出现，或出现后被老板否决（事件失败结算，§3.3）。
- 老板批准不是一次性开关：信任会随战绩、交易结果、更衣室事件浮动；信任跌破线 → 可能被收回兼任（§3.3）。

### 7.4 失败结果（failure outcomes）

| 结果 | 说明 |
|---|---|
| Offer 被拒/撤回 | 留在原身份，无惩罚；可能有冷却期。 |
| 兼任被收回 | GM+Coach → GM；轮换与训练委托 AI；记入时间线。 |
| 被解雇 | 不是 Game Over；进入 Career Opportunity 失业 → 再就业（新球队、新身份都可能）。 |
| 文化崩塌 | 组织稳定性维度大跌 → 信任结算恶化、关系事件变多；可通过长期决策修复。 |

## 8. Riley 是核心参考之一，不是唯一原型（用户定稿）

- **Riley 适合解释**：「教练如何成为球队的长期建设者」——从场边指挥一场比赛，到塑造一支球队（Heat Culture），再到以管理层身份跨越时代（1995 至今近三十年）。
- **Riley 解释不了**：从管理层进一步走向球队股权、控股和商业帝国（From Employee to Empire 的后段：小股东 → 控股老板 → 商业帝国）。这段需要**其他历史案例**支撑（候选待定，§9 Q6）。
- **长期目标**（用户定稿）：Career 2.0 的长期目标不只是赢得冠军，而是让玩家真正经历——**从场边指挥一场比赛，到塑造一支球队，再到建立一个跨越时代的篮球组织**。
