# 绝杀时刻融进每场比赛 — 设计

**状态：PROPOSED，未批准。只写文档，不动游戏代码。用户批准后由 Code Puppy 实现。**

用户原话（2026-11-26）：“把绝杀挑战移除，然后放到每一场游戏中，当最后关键时刻，让玩家自己决定。”

## §1 目标

现在绝杀挑战是个预设场景：你点进去就知道要投绝杀。真正让人记住的绝杀，发生在自己打了一整场的比赛里——有来龙去脉的绝杀才有分量。所以把“绝杀时刻”从独立入口搬进每场比赛的最后关头：符合条件时停下来，让玩家自己选出手人和打法，然后由模拟器决定进不进。

复用现有机制，不另起一套：M2b-1 的关键决策合同（submitDecision → 下一进攻回合消费）、关键时刻参与度四档、绝杀挑战现成的选人 + 打法选择器。

## §2 现状（核查过代码）

**绝杀挑战（独立入口）：** `js/engine/clutchController.js`（M2b-2，设计见 `docs/implementation/m2b-2-clutch-controller-design.md`）。唯一预设场景：2016 勇士 vs 骑士，第四节剩 12 秒，落后 3 分，你控制勇士。玩家选关键出手人 + 进攻方式（`three` / `attack`），经 `submitDecision` 交给引擎；结果页渲染 `clutchLog[0]`（结构化结果，不是猜比分）；重试永远建一个新的 GameSim。访客不用登录就能玩。入口是首页卡片 + `app.js` 里的 `show("clutch")` / `show("clutchPlay")`，**不是 modeCatalog 里的模式**（目录 13 个模式不动它）。

**比赛里的关键时刻提问（已存在）：** `js/reborn/season.js` 的 `driveGame`。没有参与度设置时是经典版：每场最多一次 takeover 提问，触发条件 `takeoverEligible`（`season.js:92`）：第四节以后、剩 ≤120 秒、分差 ≤5、己方球权、己方球员在场、无已提交决策。开了参与度设置后由 `createDecisionGate`（`js/reborn/participation.js`）按档 pacing：auto 全场 0 次；key 默认（间隔 6、每场最多 7 次，关键/分歧/明显机会才问）；high（间隔 3、最多 25 次）；full（每回合都问）。带教练指令的关键提问会扣一个暂停。

**决策合同（M2b-1，`js/engine/sim.js`）：** `submitDecision` 提交后由玩家下一进攻回合消费，暴露为 `off.temp.clutchPick`（{shooterId, needThree, role, mode}），只用一个回合；战术犯规吃掉回合时决策保留；`finish()` 会把没消费的决策以 `no_possession` 结算。送球方式按角色走（`js/engine/clutchRole.js`）：创造型/组织型持球发起，接球射手/角色球员接球投，低位走内线传球。**不加新骰子，不加命中加成**——玩家决定怎么打，不决定进不进。

## §3 触发条件（绝杀时刻，比 takeover 窗口窄）

同时满足才停下来问玩家，一场最多一次：

- 第四节或加时，剩 ≤24 秒（一个进攻回合，就是最后一攻，不是两分钟战术时间）；
- 己方球权，己方球员在场，无已提交决策；
- 落后 1–3 分，或平局。落后 1 分上篮能赢，落后 2 分能追平或反超，落后 3 分必须投三分，平局任何得分都赢；落后 4 分以上一攻赢不了，不是绝杀。

大多数比赛不会出现这个时刻（大比分、对方握有最后一攻时都没有）。这是设计意图：稀有才有分量。takeover 窗口（120 秒/5 分）保持不动，继续管一般的“关键时刻提问”。

## §4 玩家决定什么

复用绝杀挑战的选择器：**选出手人 + 选打法（三分/突破）**，走 `submitDecision`。送球方式按 `clutchRole` 来，进球与否由模拟器算。赛后总结里用挑战现成的解释文案（`clutchReasonText` / `clutchLog`）加一行，不做新结算屏。

不用 takeover 对话框的 plan/audible/pass——那是“布置战术”的决策形状，绝杀时刻要的是“谁来投、怎么投”。

**暂停：不扣。** 选出手人不是画战术；现有的关键提问扣暂停，只针对带教练指令的 takeover，对不上这件事。

## §5 与四档参与度对齐

- auto：绝杀时刻也不问（与“auto 连关键时刻也不问”一致）。
- key / high / full：绝杀时刻都问（它按定义就是 critical）。
- 绝杀提问**不占** gate 的间隔/次数 pacing（和经典版每场一次提问一样，独立于 pacing），一场最多一次，是比赛的高潮。
- 参与度每回合实时读，比赛中途改档立即生效。

## §6 独立入口去留（建议：先留着）

先留着，理由三条：它是唯一不用登录就能玩的试玩口；它是“保证能投绝杀”的版本（比赛里的时刻是稀有的）；删入口等于关掉新玩家的门。等比赛里的绝杀时刻上线、玩家玩顺了，再决定删不删。删的成本很小：入口就是首页卡片 + `app.js` 的两屏，没有 modeCatalog 改动，没有存档迁移（访客流程不存档）。

## §7 范围（v1）

- **做：** `driveGame` 走的比赛 = Reborn 赛季比赛（`rebornView.js` → `playGame`）+ 季后赛（`playoffFlow.js` → `playGame`）。赛后总结加一行绝杀解释。
- **不做：** 自定义/双人对抗等现场比赛（走 `app.js` 另一套现场驱动，v2 再做）；多人；新骰子/新概率；TEMPO_OPTIONS；模式目录改动；新结算屏。

## §8 测试 / 验收

- 触发：只在最后一攻出现（Q4/加时、≤24 秒、落后 1–3 或平局、己方球权）；大比分、对方球权、第三节、落后 4+ 都不出现。
- 档位：auto 全场沉默；key 会问；一场最多一次；中途改档立即生效。
- 模拟器权威：同种子 + 同决策 = 同结果；换出手人改变的是分布，不是剧本（没有“必进”）；比赛结束前没消费的决策按 `no_possession` 结算。
- 跑通现有 `clutchDecision` / `clutchController` / `participation` / `season` 相关测试 + 全套。
