# B4 — 大比分落后时 AI 换策略拼翻盘（已实现，2026-11-17，用户批准改 GameSim 与 Golden Hash）

## 做了什么
`js/engine/sim.js`：`updateComeback(sim, off, def)`，每个回合开头（终场脚本 `applyLateGameScripts` 之后）算一次，结果放在 `off.temp.comeback = { level, paceMult }`。

| 项 | 规则 |
|---|---|
| 触发 | 第 3 节起、落后 ≥10 分；`lateChase`（终场最后几分钟脚本）在场时不叠加 |
| 力度 | `level = clamp((落后 − 10) / 12, 0, 1)`：落后 10 → 0，22 及以上 → 1（封顶） |
| 节奏 | `paceMult = 1 + 0.12 × level × runs`，`runs` = 阵容平均速度（35→70 映射 0→1）× 体力（平均疲劳 78→38 映射 0→1）。**慢的或累的阵容不提速**，不是一律有利 |
| 三分 | `chooseShot` 的三分权重 × `(1 + 0.30 × level)`，只对 `three ≥ 55` 的人生效；"不会投就不投"的硬门槛仍在其后生效 |
| 出手欲望 | `offenseHuntLevel` 加 `0.20 × level`（读取点：持球人选择、出手、防守等 5 处） |
| 谁受影响 | CPU 一方；快速模拟（`_quiet`）下的玩家一方（自动教练）。**玩家亲自指挥时不改玩家的战术** |
| 随机性 | 无：完全由比分、节次、阵容速度和体力决定，不抽 `rng`，不碰 `Math.random` |
| 反馈 | CPU 方进入追分状态时喊一次战报："X 落后 N 分，开始抢三分、加快节奏"（回到不落后后重置） |

## 前后对比（`scripts/measure/b4-comeback.mjs`，1995/2005/2016 各 150 场，固定种子；脚本把全局 `Math.random` 也按种子固定，同一命令两次结果逐位一致）
| | 前 | 后 |
|---|---|---|
| 场均总分 | 219.8 | 221.1 |
| 场均终场分差 | 15.2 | 15.7（在噪声内，标准误约 0.5） |
| 第 4 节开始落后 ≥15 的场次 | 190（42.2%） | 182（40.4%） |
| 其中落后方翻盘 | 1（0.5%） | 3（1.6%） |
| 其中第 4 节落后分差变化 | +0.1 | **−1.6** |
| 第 4 节开始落后 ≥10 的场次 | 269（59.8%） | 261（58.0%） |
| 其中落后方翻盘 | 9（3.3%） | 16（6.1%） |
| 其中第 4 节落后分差变化 | −0.0 | **−1.0** |

参照：真实 NBA 第 4 节开始落后 15 分的球队翻盘率约 3–4%，落后 10 分约 10% 以上。前后都低于真实，现在更接近；没有出现异常比分或总分漂移。

## 局限
- 翻盘场次很少（3 与 16 场），翻盘率有小样本噪声，方向可信、幅度只是量级。
- 引擎整体偏"一边倒"（42% 的比赛第 4 节开始落后 ≥15，真实约 25–30%），这是 B4 之外的平衡问题，本次不处理。
- `hunt` 在 `calcMakeProb` 里也会影响命中率，所以追分是有代价的（硬投），这是有意保留的取舍。
- 回合级的三分占比、疲劳代价没有单独量化，只看了比赛级结果。
- 测量只覆盖历史年份 CPU 对 CPU（`runFast`）；玩家亲自指挥的实时比赛按设计不受影响，测试已断言。
