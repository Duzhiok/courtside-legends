# 返回按钮分层设计（2026-11-07 用户批准完整标准；已实施）

## 问题（2026-11-07 全屏审计，19 个 `<main>` 屏）

- 根因：`show(name)`（`js/app.js:483`）只切 `.active`，**没有历史栈、没有 `pushState`、没有 Esc 处理**；每个返回目标都是按按钮硬编码的。没有全局主页按钮（`#btn-home` 只在结算屏）。
- 现状：13 个屏有返回，但全是右上角透明 ghost 按钮（`.btn.ghost`），小、低对比、与平台标准的左上角返回相反——这就是用户说的"没有显眼的返回"。唯一例外是穿越（左上角 chevron + "返回"），也最好找。
- 缺口（按严重度）：
  1. **市场屏无返回**（`screen-market`）：没有任何返回/主页入口，只能一路向前打到比赛再"保存并离开"。唯一真正困住人的屏。
  2. **比赛屏出口埋得深**：`#btn-save-leave` 藏在底部 7 个按钮里，还要过原生 `confirm()`；暂停菜单里没有退出，只有"继续"；没有"不保存离开"的路。
  3. **传奇屏返回目标错**：从自定义页进，返回却跳主页；同级的双人/选秀都回自定义页。
  4. **结算屏返回永远回主页**：赛季/生涯流程里，自然的上一层是赛季中心/市场，今天只能靠前进的"继续"按钮回去。
  5. 小缺口：新手引导 4 步向导没有上一步（只有取消全部）；手机返回手势、Esc 全无作用。

## 分层（5 层 + 浮层）

| 层 | 界面 | 返回去哪 |
|---|---|---|
| L0 根 | 主页（4 个页签） | ——（根，页签即导航） |
| L1 中枢 | 自定义页、赛季中心、收藏、账号、市场 | 主页 |
| L2 模式/详情 | 选秀、传奇、双人、沙盒、淘汰赛、抽卡、穿越（创建流）、致谢 | 它的 L1 父级（选秀/传奇/双人→自定义页；抽卡→收藏；其余→主页） |
| L3 赛前/进行中 | 阵容设置 → 比赛 | 设置→它的来源（市场/沙盒/主页，按今天）；比赛→**暂停浮层**（绝不直回主页） |
| L4 结算 | 结算屏 | 主页，或知道来源时回来源（赛季中心/市场）——见待定 ② |
| 浮层 | 确认框、新手提示、账号拦截、暂停、我的世界面板 | 关闭即回到底下那屏；Esc/点背景可关的才关 |

## 一条返回规则

- 每个非主页屏，**左上角固定一个返回控件**：chevron + "返回"，不是主页时写明目的地（如"返回市场"、"返回自定义"）。
- 返回永远去该屏在上表里的**直接父级**；父级已不存在（打完的比赛）时回主页。浮层只关闭，不导航。
- 保留两处确认：新手引导第 1 步之后取消要确认（已选内容会清掉）；比赛中途离开永远先暂停、存档再走，绝不静默丢进度。
- 新屏用同一个挂载办法（`show()` 里按 `data-back` 挂，或一个 `mountBackButton(屏, 目标)` helper），以后新屏漏不了。

## 逐屏改动

1. 市场：加标准左上角返回 → 主页（进度已自动保存；"完成备战"前进不动）。只这一条就解开全应用的困住问题。
2. 比赛：退出挪进暂停浮层，做成显眼的主操作（"保存并离开"）；保持先存档再走的语义；暂停里的返回 = 继续（已有）。
3. 传奇：返回目标主页 → 自定义页（一行）。
4. 全屏：返回控件移到左上角，按穿越的做法统一样式（chevron + 文字、有对比度）；三个现成的好模式直接标准化：穿越的左上角位置、设置的"返回市场"式目的地命名、账号的 `accountReturnScreen` 回跳记录。
5. 结算：定一次——来源感知（赛季中心/市场）还是永远主页，定完就按它做，不留隐含行为。
6. 向导：新手引导与穿越的面试→报价→挖角流，加步内上一步（或明确写"只取消"，也行，但要写下来）。
7. `show()` 里加最小导航栈（前进压栈、返回弹栈；栈空回主页），"返回"按构造就是"上一屏"，不再逐按钮硬编码；这能根治传奇这类目标写错。Esc 接同一个弹栈（不碰浏览器历史）。

## 非目标

- 不接浏览器历史（仍是单页应用）；不改比赛流程与存档结构；不改任何玩法数值。
- 验收：每屏一断言（返回在、目标对）的新 QA 脚本 + 全量绿 + Mac 真实浏览器目视。

## 实施记录（2026-11-07，完整标准 + 三个默认项）

用户 2026-11-07 点"按完整标准做"：范围 (a) 全标准；结算来源感知；导航栈现在做；Esc 接返回。

- 单一事实源：`js/ui/navBack.js`（无 DOM，可单测）——`STATIC_BACK_TARGETS`、`STACK_BACK_SCREENS`、`EXPLICIT_BACK`、`TRANSIENT_SCREENS`、`navPush`/`navPop`、`resolveResultBack`。挂载办法最终是**共享 `.nav-back` 样式 + `show()` 里的最小栈 + `goBack()`**，不是设计里备选的 `data-back` 属性（栈已保证目标，属性会再造一份映射）。
- 逐屏落点（1–7 全做）：① 市场加左上角返回 → 主页；② 比赛退出进暂停浮层，主操作"保存并离开"，与底部 `#btn-save-leave` 共用同一个 `exitGameToHome()`（先存档再回主页）；③ 传奇改回自定义页（栈按构造给对）；④ 全屏左上角 `.nav-back`（chevron 用 CSS 边框画，不重复贴 SVG；移动端只留 chevron，与穿越一致）；⑤ 结算 `#btn-home` 来源感知（赛季中心/市场/主页）；⑥ 新手引导加"上一步"（1 步隐藏，步间保留已选），穿越面试→报价加"返回修改选择"；⑦ `show()` 压栈/`goBack()` 弹栈，Esc 接同一个 `handleBack()`（不碰浏览器历史）。
- 断言：`tests/backButtons.test.js`（17 个，节点可跑）+ `scripts/qa/back-buttons.mjs`（Playwright，Mac 跑）。

### 实施时定的判断（设计没写死的，按保守选择）

- **结算屏不另加左上角按钮**：`#btn-home` 本来就在常显的操作行里（审计评 OK），再加一个顶返回是重复。例外记在这里：结算的返回控件留在操作行，但目标按来源感知。
- **赛季返回按栈走，不按表里的 L1→主页**：从主页进回主页，从穿越"继续"进回穿越——栈给的是真实父级，表只是常见情况。
- **进市场清栈**：生涯循环是市场→设置→比赛→结算→市场；不清栈的话，市场返回会弹到设置，来回乒乓。市场返回永远主页。
- **淘汰赛结算回主页（保守）**：晋级后回对阵表走前进主操作（"晋级成功"），返回不抢它的路。
- **以下四处保留显式处理，不走栈**：设置（父级看 state：生涯/双人→市场，沙盒→沙盒，其余主页）；抽卡（返回时必须重渲染收藏，抽到的卡刚入库）；账号（`accountReturnScreen` 回跳记录）；新手引导（向导步进/取消）。
- **比赛两个出口、一个函数**：暂停浮层的"保存并离开"不弹确认——点暂停本身就是有意操作，且存档保住了比赛（回来"继续进度"接着打）；底部 `#btn-save-leave` 从活球中触发，保留原确认，再调同一函数。没有两条分叉的退出路。
- **挖角没有上一步**：挖角卡是一次性决策，不是向导；"婉拒"就是退出。面试→报价流有上一步。
- **Esc 两处让路**：确认框打开时 Esc 归框自己（原生 dialog 的 cancel）；光标在输入框/下拉框时 Esc 先失焦，不导航。
