# ADR-008：首页四空间导航（我的世界 / 我的球队 / 传奇生涯 / 自由球场）+ 离线托管联赛

- **状态**：PROPOSED（2026-11-06）。结构方向产品负责人认可；§7 的 Q1–Q6 待拍板。**纯规划，不改 GameSim、经济、账号存储、生涯存档。**
- **输入**：产品负责人 2026-11-06 的模板（My Account / My Team / 自定义·联机与单机，原话见 `DECISIONS.md` §六），外部 AI 的润色稿，三张概念图（终身勋章卡、My World 首页、My Team 页）。
- **一句话结论**：模板合理，补一个缺口就成立——**Reborn / Franchise 这两个旗舰模式必须有自己的一级入口**，不能塞进 My Team 或自定义里。

---

## 1. 对模板的评估

| 产品负责人的模板 | 评估 | 调整 |
|---|---|---|
| My Account：任务、更新、存档、趋势、广告位、联盟大消息、快速游戏、社交、社区、房子、捏的人物 | 方向对（身份 + 每日回访的理由）；但内容太杂，会变成"管理后台" | 改名 **我的世界（My World）**，只放身份、家、任务、新闻、荣誉、社交；**广告位不做**；"存档/更新"收进设置 |
| My Team：快速游戏、排位、邀请朋友对决、抽卡、培养、自由市场、卡牌、托管 | 最有价值的一块，是每天回来的主阵地 | 保留；托管改为"游戏数宽松、奖励封顶"（§4） |
| 自定义：联机 / 单机，金币挑战、随机组队、跨年代自选、未来天马行空 | 对，未来新玩法都往这里放 | 改名 **自由球场（Playground）**，按"对手类型 × 规则预设"组织（§3） |
| （缺）穿越人生、联盟经理 | 这是差异化卖点和深度底座，模板里没有位置 | 新增一级 **传奇生涯（Career）** |

**快速游戏放哪**：两处都放，意图不同，不算重复。
- 首页大按钮（现有 `play-now-hero`）：免注册、系统给阵容，给新手；
- My Team 的"快速比赛"：用自己的卡，有成长反馈。

**Clutch 关键时刻**是 GameSim 的共享能力（M2b 的 `submitDecision`），四个空间都能用，不归 My Team 独有。

## 2. 四个空间

| 一级 | 回答的问题 | 内容 |
|---|---|---|
| **我的世界** | 我是谁、今天发生了什么 | 捏的人物、家、每日任务、联盟新闻（来自当前生涯存档的模拟事件，标"游戏内"）、终身勋章墙（ADR-007 §6）、好友/社区（有后端后才显示）、设置 |
| **我的球队** | 我的球队今天有什么变化 | 永久阵容、快速比赛、排位、邀请好友对决、抽卡、卡牌收藏、培养（升星/技能）、市场、离线托管与回归报告 |
| **传奇生涯** | 我想过怎样的篮球人生 | 穿越人生（Reborn：球员/教练/GM/经典）、联盟经理（单赛季是它的经营长度，R153 已做） |
| **自由球场** | 今天想怎么玩 | 单机/本地双人/联机好友 × 自选/随机/金币预算/年代限制/主题赛（父子局等）/特殊规则 |

手机端正好是 4 个底部标签。首页本身保留"快速开打"和"继续上次生涯"两个跨空间快捷入口。

## 3. 现有功能怎么落位（核实过的现状）

| 现有 | 现在在哪 | 去哪 |
|---|---|---|
| `timeTravel`、`franchise`（含 `season` 变体） | 首页「职业经理」标签 | 传奇生涯 |
| `ranked`、抽卡（`screen-draw`）、收藏（`screen-collection`）、迎新 | 首页「我的球员」+ 账号页 | 我的球队 |
| `custom`、`career`（金币晋级赛）、`tournament`、`sandbox`/`legend`、`duel`、`familyDuel`、`draft`、`quick` | 首页「自定义」+ custom hub | 自由球场 |
| 每日任务 + 每日挑战（`dailyTasks.js`） | 抽卡页 | 我的世界（任务）/ 我的球队（奖励领取处） |
| 联机对战 + 共享市场（`online.html`，**服务端账号**的阵容） | 独立页面 | 见 §5 第 2 条：先作为"邀请好友"入口挂在我的球队，阵容合一另议 |
| 生涯内的房子（E3：`coach.housing`，生涯存档里） | 穿越生涯财务卡 | **留在生涯里**，和"我的世界"的家是两样东西 |

`modeCatalog.js` 现在每个模式有 `homeTab` 字段（players / career / custom），首页标签由它派生。第一阶段只需把这个字段的取值从 3 个改成 4 个——内部逻辑一行不动，随时可以回退。

## 4. 离线托管联赛（Auto League）

产品负责人提议每天约 20 场，外部方案建议 5 场。分歧的根源是把两件事绑在了一起：

- **场数**决定"惊喜感"——回来看到很多比赛、好几条故事；
- **奖励**决定"经济会不会崩"——金币、成长、抽卡券。

**建议：场数宽松，奖励封顶，两件事分开定。**

| 项 | 建议初值（待测量校准） |
|---|---|
| 每天可托管场数 | 20 场（按你的想法） |
| 有金币奖励的场数 | 前 5 场全额，第 6–10 场半额，之后 0 金币（只产比赛、数据和故事） |
| 成长 XP | 托管场按亲自比赛的 50% 计；和亲自比赛共用一个每日成长上限 |
| 每周 | 有奖励场数合计 ≤ 25 |
| 不做 | 托管期间不交易、不买、不抽卡、不做任何不可逆操作；不计入排位；不计入联机奖金 |

**怎么实现（低成本、可复现）**：
- **回归时结算**：下线前存托管计划（阵容 + 训练重点），上线时按"已过时间 + 每日上限"补算比赛。
- **固定随机**：每场的种子由 `hash(账号, 日期, 场次序号)` 决定，用 M2b-0 刚做好的 `GameSim({ rng })`。重开页面、读档都得到同一个结果，没法靠刷新重掷。
- **回归报告**：讲故事，不只给一行"+120 金币"——要有关键比赛、谁成长了、意外事件（伤病、连胜、手感火热）。概念图三就是这个样子。
- **防作弊边界**：账号目前存在本地（`cls_accounts_v1`），改系统时间只能骗自己的单机进度，这是可接受的。只要托管结果碰到排位或联机奖金，就必须由服务端验证；第一版干脆不碰。

## 5. 必须先想清楚的三条边界

1. **数据四层**：账号层（人物、勋章、卡牌、金币）/ 我的球队（账号下的永久阵容、托管计划）/ 生涯存档（Reborn、Franchise 各自的时间线）/ 单场（比分、Clutch 决策）。
   - 我的世界只是**展示层**，不新建一个"万能存档对象"。
   - 生涯里签下的球星不会自动变成我的球队的卡。
   - 自由球场的金币挑战用局内预算，不动账号金币。
2. **现在有两套"我的阵容"**：本地账号的卡（抽卡、排位用）和联机服务端账号的阵容（`online.html`）。我的球队要合一，就得决定以哪套为准、另一套怎么迁过来——这是存档 / 账号层的 L4 改动，要单独写 ADR，**不放进导航第一阶段**。
3. **不展示假东西**：好友动态、社区要等真有后端（ROADMAP M8 表里社交是 🔴）。在那之前**不显示**"3 条新消息"这类占位数字。联盟新闻一律标"游戏内事件"，不能让人误以为是真 NBA 公告。概念图二里"我的家"那张房间图来自 `forum.partyinmydorm.com`，只能当参考，不能放进游戏。

## 7. 待你拍板

- **Q1** 采用四个一级空间（我的世界 / 我的球队 / 传奇生涯 / 自由球场），并把 Reborn / Franchise 独立成一级入口？（推荐：是。）
- **Q2** 中文名用"我的世界 / 我的球队 / 传奇生涯 / 自由球场"？英文 My World / My Team / Career / Playground？（"我的世界"和 Minecraft 的中文名撞了，备选"我的主页 / 我的篮球人生"。）
- **Q3** 托管：每天 20 场、奖励按 §4 递减封顶？（推荐：是，数值做经济测量后再定死。）
- **Q4** 广告位：2.0 不做？（推荐：不做。将来要商业化，优先做纯外观或付费扩展内容，不和抽卡、成长绑定。）
- **Q5** N-1 导航骨架可以插在 M2b-1 之前先做吗？（推荐：可以。它只改 `homeTab` 和首页布局，不碰 `sim.js`。）
- **Q6** 两套阵容（本地卡 vs 联机账号）最终以哪套为准？（推荐：现在不定，N-5 写 ADR 时带数据再决定。）

## 8. N-1 的验收

- 所有现有模式都能进入，包括 `season` 变体和旧存档里 `lastMode` 的恢复路径。
- 免注册的快速开打仍然一键可达，并且在首屏内（复用 `home-first-screen.mjs` 的视口断言）。
- 桌面 1280×800 / 1440×900、手机 390×844 都没有横向溢出，底栏不遮挡主按钮。
- 不迁移存档，不改账号数据；`git revert` 即可整体回退。
- 首页不出现未实现功能的可点入口；未做的功能写"开发中"，并且不可点。
