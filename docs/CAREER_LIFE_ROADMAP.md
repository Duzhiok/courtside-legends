## 0. 用户原话归纳（需求来源，不改写）

1. **扩大范围**：五年封顶取消，被裁/离开后可以去别的球队继续执教。
2. **球探与选秀情报**：高中球探、试训、劝说加入、允诺；知道谁会参加下一届选秀；
   选秀名单给头像、生涯数据和表现；这些归结为"潜力"——我们是穿越回去的，知道另一条
   时间线上的历史。
3. **常规赛 + 季后赛没意思**，基本一键模拟，唯一乐趣是看数据和等交易报价。要做到每场
   都有收获、有自己玩的冲动：高光换高交易报价、连续好表现得技能、经验、潜力增长……
   **具体设计由 Code 决定**。
4. **场外因素影响生涯**：发布会、赛后表态、家庭、生活、赌钱、夜店（心情、遇到另一半）、
   孩子、私生子、买房、投资、读书会、网球、健身——**养成系**。

## 1. 设计总原则（所有阶段都遵守）

1. **新功能进新模块，`app.js` 只做接线。** `app.js` 已经 1 万多行，新逻辑一律放
   `js/career/`（纯领域逻辑，可单测）和 `js/ui/career*.js`（视图），单文件不超过 600 行。
2. **纯函数 + 不可变更新**，沿用 `eventEngine.js` / `careerContract.js` 的风格：
   输入 root，返回新 root，没变就返回同一个引用（R93 的教训：调度层别再用引用相等
   猜"有没有发生终局"，要用显式状态字段判断）。
3. **数值集中在一个配置文件** `js/career/balance.js`，不在各模块里散落魔法数字（DRY）。
4. **不编造数据。** 名册只有 NBA 赛季箱线数据（`bref,name,season,team,pos,gp,mpg,ppg,
   rpg,apg,spg,bpg,tpg,fg,tp,ft,fga,tpa`），**没有高中/大学数据、没有选秀顺位、没有
   奖项**。凡是需要这些的地方，要么用"另一条时间线的 NBA 生涯"代替，要么明确显示
   "无记录"，不允许生成假数据冒充真实历史。
5. **一键模拟不能被惩罚得太狠。** 所有"每场收获"在模拟时也有基础收益；亲自指挥给加成，
   不是唯一入口。场外窗口在批量模拟时走"生活日程预设"自动执行，不强迫玩家点 20 次弹窗。
6. **场外系统对比赛的影响必须小且可解释**（例如心情最多影响 ±2% 化学反应，并在 UI
   上写明来源），不能让养成系喧宾夺主、把篮球模拟变成掷骰子。
7. **存档兼容**：新状态放在 root 的新命名空间（`root.coach`），带 `version`；
   `js/data/saveRoot.js` 校验器同步扩充（R70 前车之鉴：新 `pendingDecision` 类型没登记
   会导致存档被拒）；旧存档读取时补默认值。注意 localStorage 配额：只存聚合值，
   不存逐场日志。
8. **双语**：所有新文案中英双份（`tests/i18n.test.js` 会钉计数）。
9. **每一步都是一个可单独提交、可回滚的小步**：单测 + 全量测试 + lint + 必要的
   1280px / 390px 浏览器回归，过了再提交。

## 2. 核心循环设计（Code 的决定，回应第 3、4 条）

### 2.1 时间单位

- **比赛日**：每场用户比赛结束 → 一张「赛后结算卡」（2.2）。
- **周**：每 4 场用户比赛 = 1 周，周末开一个「休息日窗口」，给 **3 点精力**，用来做
  场外活动（第 E 阶段）、球探行动（第 D 阶段）。不用的精力不累积（逼你做选择）。
- **休赛期**：一次性给 **10 点精力**，球探/试训/劝说/投资/家庭大事件集中在这里。
- **批量模拟**（模拟下一场/整个赛季）：窗口按玩家设定的「日程预设」自动花掉精力，
  结算汇总到一张「本段收获」卡里，而不是逐张弹窗。

### 2.2 每场有收获（第 3 条，Code 决定的方案）

每场比赛（模拟或亲自指挥）结束都会结算以下五样，在「赛后结算卡」上一屏看完：

| 收获 | 怎么来 | 有什么用 | 复用现有代码 |
|---|---|---|---|
| **球员经验 XP** | 上场分钟 × 表现评分（`grade.js`）；年轻球员系数更高 | 攒够升级 → 赛季内小幅属性成长，封顶于潜力上限 | `grade.js`、`playerDevelopment.js` |
| **高光 / 热度** | 30+ 分、三双、5+ 盖帽、单场 8+ 三分等阈值 | 球员「热度」上升 → CPU 报价价值上调、主动报价更频繁；热度按场衰减 | `tradeProposals.js` 的报价估值 |
| **领悟技能** | 连续 3 场同类高表现（已有规则表） | 学会对应技能，已有护栏（概率、上限 2 个、身高门槛） | `epiphany.js`（现在只接在排位，赛季模式没接） |
| **教练经验 + 声望** | 赢球、完成本场目标、爆冷 | 教练升级 → 教练天赋点（2.3）；声望决定后续工作机会 | 新 |
| **本场目标** | 每场随机 1 个小目标（例：新秀打满 20 分钟 / 赢下宿敌 / 全队 15 记三分） | 完成给额外 XP / 精力 / 未来知识碎片 | 新 |

额外两个"让模拟也有决定"的设计：

- **本场焦点（一键选择）**：每场赛前一个 2 秒的三选一——「练新秀」（年轻球员 XP 加成、
  胜率略降）/「保核心」（主力疲劳伤病风险降、XP 少）/「全力争胜」（胜率略升、疲劳升）。
  模拟时沿用上一场的选择，不弹窗。
- **亲自指挥加成**：亲自指挥的比赛，球员和教练 XP ×1.5，并多出一个本场目标位。
  不亲自打也有基础收益（原则 5）。
- **特殊比赛标记**：宿敌战、全国直播、复仇战（对阵交易走的老东家/前球员）、里程碑战、
  季后赛抢七——结算奖励翻倍，赛程页提前标出来，给"这场我要自己打"的理由。
- **季后赛每场调整**：系列赛每场赛前选一个针对性调整（包夹对方核心 / 限制三分 / 放慢
  节奏 / 打小个），效果持续到下一场，对手 AI 也会调整。让季后赛每一场都有决策。
- 与 Luna 的 `docs/PLAYABLE_MOMENTS_PLAN.md`（关键球时机条）互不冲突：那是比赛内的
  玩法层，本节是比赛外的奖励层；两者都落地时，关键球命中照常算进 XP 和高光。

### 2.3 教练养成（玩家自己的成长线）

教练 = 玩家本人，有自己的属性：

| 属性 | 范围 | 来源 | 作用 |
|---|---|---|---|
| 年龄 | 开局 35 岁起，每季 +1 | 时间 | 70 岁强制退休；健康事件概率 |
| 声望 | 0–100，跨球队保留 | 冠军、完成目标、发布会表现、丑闻扣 | 工作邀请质量、劝说成功率、续约条件 |
| 教练等级 / 天赋点 | 每级 1 点 | 教练 XP | 四条天赋线：战术大师 / 球员发展 / 谈判专家 / 媒体达人，每线 3 级，效果小而明确 |
| 心情 | 0–100 | 输赢、场外活动、家庭 | 发布会可选语气、场外事件分支、±2% 化学反应 |
| 个人资产 | 金额 | 年薪、投资、赌博 | 买房、生活方式、部分活动的门槛 |
| 精力 | 每周 3 点 | 时间 | 场外/球探行动的预算 |
| 未来知识 | 现有字段（开局 3） | 每季 +1，部分目标/读书会给碎片 | 揭示选秀真相、投资/赌球情报 |

## 4. 需要提前说清楚的风险

1. **应用商店分级（你之前计划上 Google Play / App Store）**：
   - 「模拟赌博」会抬高年龄分级：Apple 对频繁/强烈的模拟赌博要求最高档年龄分级；
     Google Play 走 IARC 问卷，同样会提高分级。
   - 夜店、私生子、婚恋属于成人主题，文字非露骨可以控制在较高但可接受的分级内。
   - 方案：赌博只做**文字事件 + 概率选择**，不做老虎机/轮盘这类赌场小游戏，不和任何
     真钱或内购挂钩；并在 E5 之前做成可在设置里整体关闭的模块。最终分级等 E5 做完后
     按实际内容填问卷。
2. **真实公司名**：投资里不点名真实公司（用「一家车库里起家的电脑公司」这类描述），
   避免商标问题，也避免"历史股价"被当成投资建议。
3. **真实球员 + 负面剧情**：丑闻、私生子等负面剧情**只发生在教练本人（玩家）身上**，
   不给真实球员安排虚构丑闻。
4. **范围控制**：总共约 30 步，按阶段交付，每阶段结束都是一个可玩的完整版本；
   任何一步发现牵连过大，先回到本文件改计划再动手。
5. **存档体积**：新增状态只存聚合值；C2 的 `playerDeltas` 只存有变化的球员。
